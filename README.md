# วรรณยุกต์หายไปที่ใดใน OCR ภาษาไทยแบบเปิด

Where Do Open Thai OCR Models Lose Their Tone Marks? A Study of Eight Models

ธนกฤต เสมอหน้า, ธนวัฒน์ สุริยะ และ ผศ.ดร. นนท์ คนึงสุขเกษม
คณะเทคโนโลยีสารสนเทศ สถาบันเทคโนโลยีพระจอมเกล้าเจ้าคุณทหารลาดกระบัง

Repository นี้เก็บโค้ด ผลการทดลอง และบันทึกการตัดสินใจของงานวิจัยข้างต้น ตัวบทความอยู่ที่ `docs/paper/ieee/v2/` มีทั้งฉบับภาษาไทย (`th/main_th.pdf`) และภาษาอังกฤษ (`en/main_en.pdf`)

## คำถามของงาน

อักษรไทยมีสระบน สระล่าง และวรรณยุกต์ซ้อนอยู่บนหรือล่างพยัญชนะ ในงานนี้เรียกรวมว่า mark ข่าวกับข้าวต่างกันที่ mark ตัวเดียว ถ้า OCR ทำ mark หาย คำก็เปลี่ยนความหมาย ตัวชี้วัด OCR ภาษาไทยที่ใช้กันอยู่วัดความถูกต้องของข้อความทั้งก้อน จึงบอกไม่ได้ว่า mark เป็นปัญหาหรือเปล่า

เมื่อ mark ผิด มีคำอธิบายที่เป็นไปได้สามแบบ ภาพของ mark อาจเล็กเกินไป ความรู้ภาษาของโมเดลอาจทับสิ่งที่เห็นในภาพ หรือข้อความทั้งบรรทัดอาจไม่ถูกเขียนออกมาเลย แต่ละแบบแก้ด้วยวิธีต่างกัน งานนี้วัดว่าแบบไหนเป็นตัวหลัก

## "mark หาย" ในงานนี้หมายถึงอะไร

เรานับเฉพาะ mark ในเฉลย ไม่ได้นับพยัญชนะ mark แต่ละตัวที่โมเดลเขียนไม่ถูกจะถูกจัดเข้าหนึ่งหมวด ตามสิ่งที่เกิดกับข้อความรอบตัวมัน

| หมวด | สิ่งที่เกิด | Typhoon อ่านทั้งหน้า (% ของ mark ในเฉลย) |
|---|---|---|
| ทั้งบรรทัดหาย | บรรทัดนั้นไม่อยู่ใน output เลย พยัญชนะ สระ วรรณยุกต์ และตัวเลขในบรรทัดหายไปพร้อมกัน | 2.3 |
| ข้อความขาดเป็นช่วง | mark หายไปพร้อมพยัญชนะของมัน ในบรรทัดที่ยังอยู่ คือคำหรือพยางค์หายไป | 0.7 |
| อ่านผิดพร้อมพยัญชนะ | พยัญชนะและ mark ผิดทั้งคู่ เช่น อ่านคำนั้นเป็นคำอื่น | 1.1 |
| อ่านผิดหลังพยัญชนะถูก | พยัญชนะถูก แต่สระหรือวรรณยุกต์ผิดหรือหาย | 0.4 |

ตัวเลขในตารางมาจากชุดปรับวิธี (prompt คำถามของ benchmark) mark ส่วนใหญ่จึงหายไปพร้อมข้อความทั้งบรรทัด ส่วนกรณีที่วรรณยุกต์หรือสระผิดตัวเดียวขณะที่พยัญชนะถูกมีน้อยที่สุด บรรทัดที่หายส่วนใหญ่เป็นข้อความใน infographic กราฟ โฆษณาที่แทรก และหัวเรื่อง ซึ่ง Typhoon มักเขียนแท็กแทนภาพไว้แทน

ในงานนี้เราเรียกสองหมวดแรกรวมกันว่า "ข้อความไม่ปรากฏใน output" และใช้หมวดสุดท้ายเป็นตัวแทนของการอ่าน mark ผิด เรายังไม่ได้วัดว่าช่วงที่ขาดยาวกี่คำ

## วิธีการ

เราประเมินโมเดลแบบเปิด 8 ตัวบน ThaiOCRBench สองงาน คืออ่านทั้งหน้าและอ่านข้อความสั้น โมเดลที่ใช้ได้แก่ Typhoon OCR 1.5, Pathumma-llm-vision 3.0, wayu-paxa-ocr-zero, PaddleOCR-VL-1.6, Qwen3-VL-2B, Qwen3-VL-4B, Qwen-SEA-LION-v4-4B-VL และ DeepSeek-OCR-2 ทุกตัว decode แบบ greedy ด้วย fp16 บน GPU T4

คะแนน mark ที่ใช้ให้คะแนนสระบน สระล่าง และวรรณยุกต์ทีละบรรทัดของเฉลย ไม่ว่าบรรทัดนั้นจะอยู่ตรงไหนใน output ข้อความที่เขียนเกินถูกหักคะแนน และสำเนาที่เกิดจากการวนซ้ำไม่ได้คะแนน จากนั้นจัดหมวด mark ที่เสียไปว่าหายเพราะทั้งบรรทัดไม่ปรากฏ ข้อความขาดเป็นช่วง หรืออ่านผิด

ข้อมูลแบ่งเป็นสองชุดก่อนมี output ใดๆ ชุดปรับวิธี 178 ข้อใช้พัฒนาวิธีและตั้งกฎทั้งหมด ส่วนชุดที่ล็อกไว้ 352 ข้อเปิดครั้งเดียวหลังลงทะเบียนเกณฑ์การทดสอบสามข้อไว้ล่วงหน้า (S1, S2, R1) การทดสอบทั้ง 22 รายการใช้ bootstrap 10,000 รอบและแก้ Holm ชุดเดียว

## ผลหลักบนชุดที่ล็อกไว้

ในทั้ง 8 โมเดล บนงานอ่านทั้งหน้า mark ที่เสียเพราะข้อความไม่ปรากฏใน output มีมากกว่า mark ที่อ่านผิดทั้งที่อ่านพยัญชนะถูก 4.7 ถึง 15.8 เท่า (R1 ผ่านทุกโมเดล PaddleOCR-VL ใกล้เกณฑ์ที่สุด) ถ้านับ mark ที่อ่านผิดทุกแบบ อัตราส่วนอยู่ที่ 2.0 ถึง 3.6 เท่า

การหยุด decode เมื่อพบการวนซ้ำเพิ่มค่าประมาณ mark F1 ในทั้ง 13 เซลล์ที่ลงทะเบียน (หนึ่งเซลล์คือหนึ่งโมเดลบนหนึ่งงาน) และผ่านการทดสอบใน 12 เซลล์ เพิ่มขึ้น 4.8 ถึง 35.6 จุด เซลล์ที่ไม่ผ่านคือ Pathumma บนงานอ่านทั้งหน้า (+1.3 ช่วง 95% [0.0, +3.5]) เกณฑ์ที่ลงทะเบียนกำหนดให้ทุกเซลล์ต้องผ่าน S1 จึงไม่ผ่านตามที่ลงทะเบียน การหยุดเปลี่ยน output ที่จบเองเพียง 1 จาก 2,400 รายการ

บนชุดปรับวิธี เมื่อป้อนข้อความที่ถูกจนถึงตำแหน่งของ mark แล้วให้โมเดลเลือก Typhoon และ Pathumma เลือกวรรณยุกต์ถูกราว 99% และภาพช่วยเพิ่มเพียงราว 1 จุด Qwen3-VL-4B เลือกถูกบ่อยพอกัน แต่ตอนเขียนหน้าเองยังอ่านวรรณยุกต์ผิดราว 1 ตัวใน 11 การหักความรู้ภาษาออกด้วย contrastive decoding ที่เราเขียนขึ้นใหม่ (M3ID-form) ลบวรรณยุกต์ที่ถูกต้องออกไปด้วย

## ขอบเขตของข้อสรุป

ผลทั้งหมดเป็นผลเบื้องต้น (`PRELIMINARY_PILOT_NOT_GATE_EVIDENCE`) มาจาก benchmark เดียว และใช้กับ 8 โมเดลนี้เท่านั้น output บอกได้เพียงว่าข้อความไม่ปรากฏ ยังบอกไม่ได้ว่าโมเดลมองไม่เห็นหรือเห็นแล้วไม่เขียน งานนี้ไม่มีกลุ่มเทียบของอักขระที่ไม่ใช่ mark จึงไม่ได้แสดงว่า mark หายในอัตราสูงกว่าพยัญชนะ

โมเดลถูกเทียบตามที่ผู้พัฒนาเผยแพร่ จำนวน visual token และความละเอียดของภาพจึงไม่เท่ากัน Typhoon และ Pathumma ทำคะแนนใกล้กันจนแยกไม่ออก และอาจมีข้อมูลซ้อนกับ benchmark เราจึงไม่จัดอันดับสองตัวนี้ การหยุดบนชุดที่ล็อกไว้คำนวณแบบ offline ส่วนการหยุดระหว่าง decode จริงตรวจบนชุดปรับวิธีเท่านั้น โดยได้ผลตรงกับการตัดแบบ offline ทุกตัวอักษรใน 185 จาก 185 ข้อ

## ประวัติของ repository

โปรเจกต์เริ่มจากคำถามว่ารายละเอียดเล็กของตัวอักษรทนต่อการลด visual token ได้แค่ไหน ช่วงนั้นทดลองทั้ง token pruning หลัง Vision Encoder และการลดความละเอียดภาพ แล้วพบว่า pruning หลัง encoder ทำให้ CER สูงขึ้นโดยไม่ช่วยความเร็วที่วัดได้ เพราะเวลาส่วนใหญ่อยู่ที่ขั้น decode เป้าหมายจึงเปลี่ยนเป็นการวัดข้อผิดของ mark โดยตรงเมื่อปลายเดือนกันยายน 2026 โค้ดในโฟลเดอร์อย่าง `region_ocr` และ `input_side` เป็นงานจากช่วงแรกนั้น รายละเอียดและเหตุผลของการตัดสินใจแต่ละครั้งอยู่ใน `docs/DECISION_LOG.md`

ห้ามใช้คำว่า "best", "state-of-the-art" กับ Typhoon W2 และ W4 วัด Pathumma แล้ว และแยกจาก Typhoon ไม่ออก (ช่วงความเชื่อมั่นรวม 0) จึงยังห้ามใช้ ชื่อเรื่องที่ใช้ในต้นฉบับคือ *Absent, Not Misread* เพราะ "Not Reading, Not Misreading" แรงเกินไปสำหรับ Qwen3-VL-4B ที่อ่าน mark ผิดตอนเขียนหน้าเองราว 1 ใน 11 (W3)

## Abstract (โครง 5 ประโยค)

1. **ปัญหา:** OCR ภาษาไทยต้องอ่านสระบน สระล่าง และวรรณยุกต์ ซึ่งตัวชี้วัดทั่วไป (CER) ไม่แยกให้เห็น และลงโทษลำดับการอ่าน
2. **วิธีวัด:** เสนอคะแนน mark แบบไม่สนลำดับ ที่ยังหักข้อความเกินและข้อความที่วนซ้ำ
3. **ผลวินิจฉัย:** บน ThaiOCRBench mark ที่หายส่วนใหญ่ไม่ปรากฏใน output (วนซ้ำ หาไม่เจอ ข้ามบรรทัด) บอกไม่ได้ว่าโมเดลมองไม่เห็นหรือเห็นแล้วไม่เขียน ไม่ใช่การอ่าน mark ผิด และเมื่อคำก่อนหน้าถูก โมเดลเลือกวรรณยุกต์ถูกราว 99% แม้ไม่ดูภาพ **[W1, W3, W4 เสร็จ: ถูกต้องกับ fine-tune ภาษาไทยสองตัว ส่วน Qwen3-VL-4B รู้ mark แต่อ่านผิดบางตัวตอน generate จึงเป็นจริงเพียงบางส่วน]**
4. **วิธีแก้:** การหยุดเมื่อเจอการวนซ้ำไม่เปลี่ยน output ที่ไม่วนซ้ำเลย และเพิ่มคะแนน mark ขณะที่ repetition penalty และ decoding ที่หักความรู้ภาษาทำให้วรรณยุกต์แย่ลง **[W4: เพิ่ม mark F1 ใน 12 จาก 13 เซลล์ที่ลงทะเบียนไว้ Pathumma Full-page ไม่ผ่าน เปลี่ยน output ที่จบเอง 1 จาก 2,400]**
5. **ขอบเขต:** ทดลองกับโมเดลแบบเปิดแปดตัวบนชุด locked และหกตัวบนชุด calibration

## 1. Introduction (≈ 0.6 หน้า)

- **ทำไมต้องสนใจ mark:** mark เปลี่ยนความหมายคำ และงานเดิมรายงานแค่ CER หรือคะแนนรวมของ benchmark
- **สิ่งที่ยังไม่รู้:** ความผิดของ mark มาจากการมองไม่เห็น หรือจากความรู้ภาษาที่ทับหลักฐานในภาพ (RQ-A)
- **Contributions:**
  1. ตัวชี้วัด mark แบบไม่สนลำดับและกันคะแนนจากข้อความที่วนซ้ำ (§3)
  2. การแยกสาเหตุความผิดของ mark ข้าม N โมเดล (§4)
  3. ผลของ training-free decoding ต่อ mark: การหยุดเมื่อวนซ้ำ เทียบกับวิธีที่นิยมใช้ (§5)

## 3. Measuring marks without charging reading order (≈ 0.6 หน้า)

- **นิยาม:**
  - จับคู่บรรทัดเฉลยกับ output ทีละบรรทัด
  - ที่เหลือจับคู่แบบ global
  - precision นับทุก mark ใน output
  - ส่วนที่วนซ้ำถูกหักแต่ไม่ได้ recall
  - ที่มา: `ORDER_FREE_MARK_METRIC_DRAFT.md` §2, §6, §8
- **ตรวจความถูกต้องของตัวชี้วัด:** การอ่านซ้ำสองรอบต่อกัน (CAT) ต้องได้คะแนนต่ำกว่า และ recall ของโมเดลตั้งต้นไม่เปลี่ยน (§7)
- **ตาราง 1:** Typhoon แบบไม่สนลำดับ 94.9 เทียบแบบบังคับลำดับ 93.1 และผลของการกันคะแนนวนซ้ำ (โมเดลตั้งต้น 41.0 → 34.4)

## 4. Where marks are lost (≈ 1.2 หน้า)

- **ตาราง 2 (ตารางหลัก) [เสร็จ: ตารางที่ 4 ในต้นฉบับ]:** ต่อโมเดล ประกอบด้วย
  - คะแนน mark (v2 และแบบกันวนซ้ำ)
  - วรรณยุกต์ผิดเมื่อพยัญชนะถูก
  - สัดส่วนสาเหตุ: คนละลำดับ / หายทั้งบรรทัด / หายบางช่วง / อ่านผิด
  - ส่วนที่มาจากการวนซ้ำ
  - ตอนนี้ครบแปดโมเดลบนชุด locked (CLAIMS ข้อ 12–14, 17) และหกโมเดลบน calibration (ข้อ 11)
- **รูป 1:** แถบซ้อนแสดงสาเหตุ ต่อโมเดล
- **§4.2 ภาพหรือความรู้ภาษา (T2) [เสร็จ: W3 ใน CLAIMS ข้อ 15]:**
  - Typhoon เห็นภาพ 99.7 / ไม่เห็น 98.8
  - โมเดลตั้งต้น 98.1 / 98.9
  - Pathumma เห็นภาพ 99.7 / ไม่เห็น 98.7 และ Qwen3-VL-4B 98.7 / 99.1
  - ต้องเขียนชัดว่าเป็น forced choice ที่ให้คำก่อนหน้าที่ถูก และเมื่อเขียนหน้าเอง Qwen3-VL-4B ถูกเพียง 91.3% ที่ตำแหน่งซึ่งอ่านพยัญชนะถูก
- **§4.3 หาไม่เจอ หรืออ่านผิด:** ตัดเฉพาะกรอบให้ Typhoon หาเจอ 7% → 99% (F1 ของเพื่อน, `FIND_VS_READ_F1_RESULTS.md`) ใส่พร้อมข้อจำกัดเรื่องกลุ่มย่อยที่ถูกเลือก

## 5. Training-free decoding and marks (≈ 0.8 หน้า)

- **ตาราง 3:** วิธีแก้การวนซ้ำ 3 วิธี × โมเดล คอลัมน์คือ ทุก output / เฉพาะ output ที่ไม่วนซ้ำ / สัดส่วน output ที่ไม่วนซ้ำแต่ถูกเปลี่ยน
  - Typhoon (T5, T5b) บน calibration ส่วนโมเดลอื่นอยู่ในตารางที่ 3 (calibration, offline) และตารางที่ 4 (ผลยืนยันบนชุด locked, CLAIMS ข้อ 12–13)
  - ตัวตรวจตอน decode จริง: calibration เท่านั้น (ข้อ 16)
- **§5.2 การหักความรู้ภาษา:**
  - contrastive rescoring ของ T2: λ 0 / 0.5 / 1 → 99.7 / 97.3 / 42.3
  - R1/R2 แบบ M3ID-form ทำให้วรรณยุกต์หาย
- **§5.3 ความเร็ว:** speculative decoding เร็วขึ้น 1.14–1.15 เท่า คำตอบเหมือนเดิมยกเว้นจุดที่สองตัวเลือกคะแนนเกือบเท่ากันใน fp16 ถ้า W4 รวมทั้งสองวิธี ให้ใส่เวลารวมด้วย

## 6. Limitations (≈ 0.3 หน้า)

- **ข้อมูล:** benchmark เดียว และงาน 2 ประเภท
- **ลำดับการออกแบบ:** กฎการหยุดตั้งหลังเห็นข้อมูลชุด calibration (W4 ยืนยันบนชุด locked แต่ผลยังเป็น pilot ไม่ใช่หลักฐาน gate และ S1 ตามที่ลงทะเบียนไม่ผ่านหนึ่งเซลล์)
- **การเทียบโมเดล:** เทียบแบบที่ปล่อยมา งบ visual token จึงไม่เท่ากัน และ Paddle กับ Wayu ไม่ได้ออกแบบมาอ่านทั้งหน้า
- **การแยกสาเหตุ:** อัตโนมัติ ไม่ได้ให้คนตรวจ
- **เงื่อนไขการใช้ Typhoon:** ใช้ revision ที่ปล่อยภายใต้ Apache-2.0 อย่างเดียว ดู Decision Log 2026-09-25

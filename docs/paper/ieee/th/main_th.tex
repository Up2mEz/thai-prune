\begin{abstract}
\noindent
Vision-Language Model (VLM) แบบเปิดสำหรับ OCR ภาษาไทยอ่านหน้าเอกสารได้ถูกต้องเกือบทั้งหน้าแล้ว แต่ยังมีคำถามที่สำคัญในทางปฏิบัติอยู่ข้อหนึ่ง คือ สระและวรรณยุกต์ของไทยมีขนาดเล็ก และเครื่องหมายเพียงตัวเดียวก็เปลี่ยนความหมายของคำได้ งานนี้จึงถามว่าเครื่องหมายเหล่านี้หายไปที่ใด ไม่ได้ถามเพียงว่าหายไปเท่าไร เราเสนอคะแนนที่วัดเครื่องหมายโดยไม่หักคะแนนเรื่องลำดับการอ่าน หักคะแนนข้อความที่เขียนเกิน และไม่ให้คะแนนกับข้อความที่ซ้ำจากการวนซ้ำ บนชุด calibration ของ ThaiOCRBench โมเดล Typhoon OCR 1.5 (2B) เขียนวรรณยุกต์ผิดเพียง 0.65\% ในตำแหน่งที่อ่านพยัญชนะฐานถูกต้อง และเมื่อให้ข้อความก่อนหน้าที่ถูกต้อง โมเดลเลือกวรรณยุกต์ถูกต้อง 98.8\% แม้ไม่เห็นภาพ เครื่องหมายที่หายไปส่วนใหญ่ไม่ได้ถูกอ่านเลย กล่าวคือ บรรทัดหายไปทั้งบรรทัด ข้อความขาดเป็นช่วง หรือ output ถูกการวนซ้ำกินไป ในบรรดาวิธี decode ที่ไม่ต้อง train เพิ่ม การหยุดเมื่อตรวจพบการวนซ้ำไม่เปลี่ยน output ที่ไม่วนซ้ำเลยและเพิ่มคะแนน mark F1 ขึ้น 0.8 จุดสำหรับ Typhoon และ 10.8 จุดสำหรับโมเดลไทยขนาด 0.9B ส่วน repetition penalty ทำให้ F1 ของหน้าที่ไม่วนซ้ำลดลง และการหักความรู้ภาษาออกทำให้วรรณยุกต์ที่ถูกอยู่แล้วหายไป \todo{ผลของโมเดลอื่นและการยืนยันบนชุดข้อมูลที่เก็บไว้ (locked split) ยังไม่เสร็จ} ผลทั้งหมดเป็นผลเบื้องต้น ใช้ benchmark เดียว ชุดข้อมูล calibration และกฎบางข้อกำหนดหลังจากเห็นข้อมูลแล้ว
\end{abstract}

\section{Introduction}
อักษรไทยเขียนพยัญชนะเป็นแนวหลัก แล้วมีเครื่องหมายซ้อนอยู่ด้านบนและด้านล่าง ได้แก่ สระบน สระล่าง และวรรณยุกต์สี่รูป เครื่องหมายเพียงตัวเดียวเปลี่ยนทั้งความหมายและเสียงของคำได้ (``ข่าว'' กับ ``ข้าว'') การถอดข้อความที่ทำเครื่องหมายหายหรือสลับผิดตัวจึงผิดสำหรับผู้อ่าน แม้ตัวอักษรเกือบทั้งหมดจะถูกต้อง ทว่าการประเมิน OCR ภาษาไทยในปัจจุบันใช้ตัวชี้วัดระดับข้อความทั้งก้อน ได้แก่ ความทับซ้อนของ n-gram และ normalized edit distance ใน ThaiOCRBench \cite{nonesung2025thaiocrbench} และ character error rate ในงานอื่น ตัวเลขเหล่านี้บอกไม่ได้ว่าปัญหาอยู่ที่เครื่องหมายหรือไม่ และคะแนนที่เทียบทั้งลำดับยังลงโทษโมเดลที่อ่านคอลัมน์ของหน้าในลำดับต่างจากเฉลยด้วย

ปัจจุบันมี VLM แบบเปิดที่ train มาเพื่อ OCR ภาษาไทยแล้ว \cite{nonesung2026typhoonocr,nectec2026pathumma,pipatanakul2026synthetic} เมื่อโมเดลเหล่านี้ทำเครื่องหมายผิด ผิดเพราะอะไร หลักฐานในภาพของเครื่องหมายขนาดเล็กอาจอ่อนหรือหายไป ความรู้ภาษาของโมเดลอาจทับหลักฐานในภาพ หรือโมเดลอาจไม่ได้อ่านเครื่องหมายนั้นเลย เพราะข้ามบรรทัด หาข้อความไม่เจอ หรือติดการวนซ้ำ สาเหตุแต่ละทางต้องแก้ต่างกัน ถ้าปัญหาอยู่ที่ภาพ ต้องอ่านซ้ำหรือขยายภาพ ถ้าปัญหาอยู่ที่ความรู้ภาษา ต้องหักความรู้ภาษาออกแบบ contrastive decoding \cite{leng2024vcd,favero2024m3id} และถ้าข้อความไม่ถูกอ่านเลย ต้องแก้ที่วิธี decode หรือการหาตำแหน่งข้อความ

เราศึกษาคำถามนี้บน ThaiOCRBench กับ Typhoon OCR 1.5 และ checkpoint แบบเปิดอีกสี่ตัว ในงานอ่านทั้งหน้าและงานอ่านข้อความสั้น งานนี้มีส่วนร่วมสามข้อ
\begin{enumerate}
\item \textbf{คะแนนเครื่องหมายที่ไม่หักเรื่องลำดับการอ่าน} (หัวข้อ~\ref{sec:metric}) ให้คะแนนสระบน สระล่าง และวรรณยุกต์ทีละบรรทัดของเฉลย ไม่ว่าบรรทัดนั้นจะอยู่ตรงไหนของ output หักคะแนนข้อความที่เขียนเกิน และไม่ให้คะแนนกับสำเนาที่ซ้ำจากการวนซ้ำ
\item \textbf{การวินิจฉัยว่าเครื่องหมายหายไปที่ใด} (หัวข้อ~\ref{sec:where}) หลังจากอ่านพยัญชนะถูก Typhoon เขียนวรรณยุกต์ผิดเพียง 0.65\% และเมื่อให้ข้อความก่อนหน้าที่ถูกต้อง โมเดลเลือกวรรณยุกต์ถูก 98.8\% แม้ไม่เห็นภาพ เครื่องหมายที่หายส่วนใหญ่ไม่ได้ถูกอ่านเลย \todo{ผลวินิจฉัยเดียวกันกับโมเดลอื่น}
\item \textbf{ผลของวิธี decode ที่ไม่ต้อง train ต่อเครื่องหมาย} (หัวข้อ~\ref{sec:decoding}) การหยุดเมื่อตรวจพบการวนซ้ำไม่เปลี่ยน output ที่ไม่วนซ้ำเลยและเพิ่มคะแนน mark F1 repetition penalty ทำให้ F1 ของหน้าที่ไม่วนซ้ำลดลง และการหักความรู้ภาษาออกทำให้วรรณยุกต์ที่ถูกอยู่แล้วหายไป \todo{การยืนยันบน locked split}
\end{enumerate}
สำหรับโมเดลที่ศึกษา ความผิดของเครื่องหมายที่ยังเหลือในโมเดล OCR ภาษาไทยที่เก่งอยู่แล้วเกิดขึ้นก่อนถึงตัวเครื่องหมาย จุดที่แก้ได้จริงจึงอยู่ที่วิธี decode และการหาข้อความให้เจอ ไม่ใช่การทำให้มองวรรณยุกต์ชัดขึ้น

\section{Related Work}
\textbf{OCR ภาษาไทยด้วย VLM} ThaiOCRBench \cite{nonesung2025thaiocrbench} ประเมิน VLM ทั้งแบบปิดและแบบเปิดบนงานเอกสารภาษาไทย รวมถึงงานอ่านทั้งหน้าและงานอ่านข้อความสั้น โดยใช้ตัวชี้วัดแบบความทับซ้อนของ n-gram และ edit distance (BLEU, METEOR, F1 และ normalized Levenshtein ส่วนงานอ่านข้อความสั้นใช้ ANLS) บทนำของงานระบุว่า diacritic ที่ซ้อนกันเป็นความยากของภาษาไทย แต่ไม่มีคะแนนที่แยกเครื่องหมายออกมา หลังจากนั้นมี OCR ภาษาไทยแบบเปิดออกมาหลายตัว ได้แก่ Typhoon OCR \cite{nonesung2026typhoonocr} เวอร์ชัน 1.5 ซึ่งเป็น full fine-tune ของ Qwen3-VL-2B \cite{bai2025qwen3vl} และผู้เขียนระบุว่า infographic เป็นจุดที่ยังต้องปรับปรุง Pathumma-llm-vision 3.0 \cite{nectec2026pathumma} ซึ่งเป็น fine-tune ของ Qwen3-VL-2B อีกตัว และ wayu-paxa-ocr-zero \cite{pipatanakul2026synthetic} ซึ่งเป็น fine-tune ของ PaddleOCR-VL \cite{cui2025paddleocrvl} ด้วยหน้าเอกสารไทยสังเคราะห์ ทุกงานรายงานความแม่นยำรวม ส่วนงานของเราถามว่าเครื่องหมายหายไปที่ใด

\textbf{Diacritic ใน OCR} อักษรที่มี diacritic มากเป็นที่รู้กันว่ายากสำหรับ OCR มีงานเสนอการแก้ข้อความหลัง OCR สำหรับ diacritic ภาษาเวียดนาม \cite{do2025reference} และงานประเมิน OCR ภาษาอาหรับแยกข้อความที่มี diacritic เป็นเงื่อนไขต่างหาก \cite{elsafty2025arabic} เราไม่พบงานที่ให้คะแนนเครื่องหมายภาษาไทยแยกจากลำดับการอ่านและข้อความที่เขียนเกิน

\textbf{การวนซ้ำและการตกหล่น} การ decode ที่เลือกคำตามความน่าจะเป็นสูงสุดทำให้ข้อความวนซ้ำ \cite{holtzman2020curious} และโมเดล OCR เอกสารก็เสื่อมในแบบเดียวกัน Nougat รายงานหน้าที่โมเดลพิมพ์ประโยคเดิมซ้ำและหยุด generate เมื่อสัญญาณความแปรปรวนของ logit ลดลง \cite{blecher2024nougat} olmOCR สุ่มใหม่ด้วย temperature ที่สูงขึ้น \cite{poznanski2025olmocr} pipeline ของ PaddleOCR-VL ตัดข้อความซ้ำหลัง decode เสร็จ \cite{paddlex2025truncate} และโค้ดที่ DeepSeek-OCR เผยแพร่ห้าม n-gram ซ้ำภายในหน้าต่างหนึ่ง \cite{deepseekocr2025code,wei2025deepseekocr} CC-OCR วัดการวนซ้ำในฐานะ hallucination แบบหนึ่งของ OCR \cite{yang2025ccocr} งานเหล่านี้มองการวนซ้ำเป็นสิ่งที่ต้องตรวจจับหรือหลีกเลี่ยง ส่วนเราวัดว่าวิธีแก้แต่ละแบบทำให้เครื่องหมายในหน้าที่ไม่วนซ้ำเสียไปเท่าไร รวมถึง repetition penalty ของ CTRL \cite{keskar2019ctrl} ที่ package OCR บางตัวเปิดไว้เป็นค่าเริ่มต้น

\textbf{ความรู้ภาษาและ decoding ที่ไม่ต้อง train} Contrastive decoding ลด hallucination ของ VLM โดยลดน้ำหนักสิ่งที่โมเดลจะทำนายเมื่อไม่มีภาพหรือภาพถูกทำให้เสีย ได้แก่ VCD \cite{leng2024vcd}, M3ID \cite{favero2024m3id} และ PAI \cite{liu2024pai} วิธีเหล่านี้ตั้งสมมติฐานว่าความรู้ภาษาเป็นต้นเหตุ แต่สำหรับวรรณยุกต์ไทยเราพบว่าความรู้ภาษามักถูกอยู่แล้ว วิธีที่เราใช้เป็นการเขียนใหม่ จึงเรียกว่า ``M3ID-form'' และ ``PAI-style'' ส่วน speculative decoding \cite{leviathan2023speculative} ซึ่งในงานนี้ใช้ prompt lookup เป็นตัวร่าง \cite{saxena2023pld} ทำให้ decode เร็วขึ้นโดย output ไม่เปลี่ยนเมื่อคำนวณแบบแม่นยำ

\section{Scoring Marks Without Charging Reading Order}\label{sec:metric}
เครื่องหมายที่เราวัด (เรียกว่า \emph{mark}) ได้แก่ สระบนหกตัว (ั ิ ี ึ ื ็) สระล่างสองตัว (ุ ู) และวรรณยุกต์สี่รูป (่ ้ ๊ ๋) เฉลยของหน้าเต็มมีหลายบรรทัด และโมเดลอาจอ่านคอลัมน์ของหน้าในลำดับต่างจากเฉลย การเทียบแบบ global alignment จึงนับ mark ที่อ่านถูกว่าผิด

\textbf{นิยาม} เราประมวลผลบรรทัดของเฉลยที่ยาวอย่างน้อยแปดตัวอักษร เรียงจากบรรทัดยาวไปสั้น แต่ละบรรทัดหาช่วงของ output ที่ตรงกับบรรทัดนั้นด้วย character error rate ต่ำกว่า 40\% โดยปิดบังอักขระที่ถูกจับคู่ไปแล้ว ให้คะแนน mark ที่ตรงกัน และจองช่วงนั้นไว้ เพื่อไม่ให้ช่วงเดียวของ output ให้คะแนนสองบรรทัด บรรทัดที่เหลือถูกจัดแนวแบบ global ตามลำดับของเฉลยกับ output ที่ตัดอักขระที่จองไว้ออกทั้งหมด หากไม่มีขั้นนี้ mark ในบรรทัดที่อ่านคลาดเคลื่อนจะหลุดไป และเวอร์ชันแรกของเราไม่ผ่านการตรวจกับโมเดลตั้งต้น Recall คือ mark ที่ได้คะแนนหารด้วย mark ในเฉลย ส่วน precision คือ mark ที่ได้คะแนนหารด้วย mark \emph{ทั้งหมด} ใน output จึงหักคะแนนข้อความที่เขียนเกิน F1 คิดแบบ micro-average ทุกข้อ

\textbf{แบบกันการวนซ้ำ} ในแบบนี้ คะแนนคิดจาก output ที่ย่อทุกช่วงที่วนซ้ำให้เหลือหนึ่งสำเนา ช่วงที่วนซ้ำคือหน่วยยาว 4--400 ตัวอักษรที่มีตัวอักษร ซ้ำกันเป๊ะอย่างน้อยแปดครั้ง (หกครั้งสำหรับหน่วยที่ยาว 50 ตัวอักษรขึ้นไป) ส่วน precision ยังนับ mark ทุกตัวของ output เต็ม สำเนาที่ซ้ำจึงถูกหักคะแนนแต่ไม่ได้ recall แบบนี้เพิ่มขึ้นหลังจากผู้ร่วมงานสังเกตว่า alignment จับคู่สำเนาของหน่วยเดียวที่ซ้ำ 434 ครั้งเข้ากับพยางค์ทั่วไปในเฉลย ถ้าไม่มีการวนซ้ำ คะแนนทั้งสองแบบเท่ากัน

\textbf{การตรวจสอบ} การอ่านหน้าเดียวกันสองรอบต่อกันได้คะแนนต่ำกว่าการอ่านรอบเดียวที่ดีกว่ามาก recall ของโมเดลตั้งต้นต่างจาก global alignment ไม่เกิน 0.3 จุดในทุกเซลล์ และ recall ของ Typhoon บนหน้าเต็มเพิ่มขึ้น 1.6--1.8 จุดเมื่อไม่หักเรื่องลำดับ การหักคะแนนเรื่องลำดับอย่างเดียวทำให้ mark F1 ของ Typhoon บนหน้าเต็มลดจาก 94.9 เหลือ 93.1 (BQ; ส่วน TC จาก 95.3 เหลือ 93.7 โดย BQ และ TC นิยามในหัวข้อถัดไป) ส่วนโมเดลตั้งต้นแทบไม่ได้รับผลกระทบ

\section{Experimental Setup}\label{sec:setup}
\textbf{ข้อมูล} เราใช้ชุด test ของ ThaiOCRBench \cite{nonesung2025thaiocrbench} สองงาน คืองานอ่านทั้งหน้าและงานอ่านข้อความสั้น ชุด calibration สุ่มแบบกำหนด seed ไว้ 30\% แบ่งชั้นตามงานและหมวด มีงานอ่านทั้งหน้า 69 ข้อ และงานอ่านข้อความสั้น 109 ข้อ ชุด locked ซึ่งเป็นส่วนที่เหลือ 70\% ยังไม่ถูกเปิด เรารายงาน output และคะแนนรายข้อ โดยไม่เผยแพร่ภาพของ benchmark

\subsection{Typhoon's Lost Marks Are Mostly Not Read}
บนหน้าเต็ม Typhoon ทำ mark ผิด 6.2\% (BQ) และ 7.1\% (TC) ของ mark ในเฉลยทั้งหมด เราจัดแต่ละข้อผิดเข้าสาเหตุเดียวโดยอัตโนมัติ (รูปที่~\ref{fig:causes}) ได้แก่ บรรทัดถูกอ่านในลำดับอื่น (มีช่วงของ output ตรงกับบรรทัดนั้นด้วย character error rate ต่ำกว่า 20\% สำหรับบรรทัดที่ยาวอย่างน้อยแปดตัวอักษร) บรรทัดหายไปทั้งบรรทัด ข้อความขาดเป็นช่วงภายในบรรทัดที่เก็บไว้ หรืออ่าน mark ผิดตัว บรรทัดที่หายทั้งบรรทัดคิดเป็น 2.3\% (BQ) และ 2.9\% (TC) ของ mark ข้อความที่ขาดเป็นช่วงคิดเป็น 0.7\% และ 0.8\% และการอ่านผิดตัวคิดเป็น 1.5\% และ 2.4\% ส่วนลำดับการอ่านอย่างเดียวคิดเป็น 1.6\% และ 0.9\% ซึ่งไม่ใช่ความผิดพลาดของการอ่าน เมื่อเปิดดู output จริง บรรทัดที่หายส่วนใหญ่เป็นข้อความใน infographic และกราฟ โฆษณาที่แทรกอยู่ รวมถึงชื่อเรื่องและส่วนประกอบของหน้า ซึ่ง Typhoon เขียนเป็นตัวแทนภาพไว้ สอดคล้องกับที่ผู้พัฒนาระบุเรื่อง infographic \cite{nonesung2026typhoonocr} ส่วนโมเดลตั้งต้นสูญเสีย mark ราว 41\% การจัดสาเหตุเป็นแบบอัตโนมัติ และเราตรวจภาพหน้าเอกสารเฉพาะหกหน้าที่มี mark ที่หายเป็นส่วนใหญ่ \todo{การจัดสาเหตุสำหรับโมเดลอื่น}

\subsection{Given the Right Context, the Prior Is Already Right}
ในการทดสอบแบบเลือกคำตอบบังคับ (forced choice) เราป้อนข้อความที่ถูกต้องจนถึงตำแหน่งของ mark แล้วให้โมเดลให้คะแนนตัวเลือกที่เป็นไปได้ของ mark นั้นทั้งแบบมีภาพและไม่มีภาพ (fp32, tokenize ในบริบทเดียวกัน) Typhoon เลือกวรรณยุกต์ถูกบนหน้าเต็ม 99.7\% เมื่อมีภาพ และ 98.8\% เมื่อไม่มีภาพ ส่วนโมเดลตั้งต้นได้ 98.1\% และ 98.9\% (รูปที่~\ref{fig:prior} ด้านซ้าย) ภาพช่วยเพิ่ม 0.9 จุดให้ Typhoon และลดลง 0.8 จุดสำหรับโมเดลตั้งต้น การทดสอบนี้เป็นการเลือกตอบแบบบังคับภายใต้บริบทที่ถูกต้อง ไม่ใช่การ generate จริง ในคู่โมเดลนี้เพียงคู่เดียว โมเดลที่ train เฉพาะทางได้ประโยชน์จากภาพมากกว่าโมเดลตั้งต้น ไม่ใช่น้อยกว่า และเราไม่ขยายความไปเกินกว่านี้ \todo{การทดสอบเดียวกันกับ Pathumma และ Qwen3-VL-4B}

\textbf{ความมั่นใจของโมเดล} ความน่าจะเป็นของ token ที่ Typhoon เขียนเองบอกตำแหน่งที่อ่าน mark ผิดได้ ค่าความน่าจะเป็นต่ำสุดของ token ภายในกลุ่มอักขระแยก mark ที่อ่านผิดออกจาก mark ที่ถูกด้วย AUROC 0.918 (BQ) และ 0.935 (TC) บน output แบบ greedy ของโมเดลเอง

\section{Training-Free Decoding and Marks}\label{sec:decoding}
\subsection{Loops Are Rare and Costly}
จาก output ของ Typhoon 356 รายการ (BQ และ TC ทั้งสองงาน) มี 11 รายการที่วนซ้ำ หน้าที่วนซ้ำเพียง 2--5 หน้าครอบครอง 68--76\% ของ mark ที่เขียนเกินทั้งหมดในแต่ละเซลล์ ถ้าไม่มีหน้าเหล่านี้ F1 บนหน้าเต็ม (BQ) จะเป็น 97.4 แทน 94.9 ค่านี้คือเพดานที่ได้จากการตัดหน้าเหล่านั้นออก ไม่ใช่ผลของวิธีใด

\subsection{Three Ways to Handle a Loop}
เราเทียบวิธีจัดการการวนซ้ำสามวิธีของ Typhoon กับ greedy decoding (รูปที่~\ref{fig:decoders} หน้าเต็ม BQ)
\begin{itemize}
\item \textbf{Repetition penalty 1.1} ซึ่งเป็นค่าต้านการวนซ้ำใน package ของ Typhoon เอง ใช้ penalty แบบเดียวกับ CTRL \cite{keskar2019ctrl}
\item \textbf{n-gram blocking} แบบเดียวกับโค้ดของ DeepSeek-OCR คือห้าม 30-gram ซ้ำภายใน 90 token
\item \textbf{หยุดเมื่อตรวจพบการวนซ้ำ} เมื่อหน่วยข้อความซ้ำแปดครั้ง (หกครั้งสำหรับหน่วยที่ยาว 50 ตัวอักษรขึ้นไป) การ decode หยุดที่สำเนาแรก greedy decoding กำหนดผลล่วงหน้าตาม prefix เราจึงคำนวณจุดตัดแบบ offline จาก output greedy ที่ครบแล้ว ส่วนการทำตอน decode จริง เรายังไม่ได้ตรวจเทียบกับผลนี้
\end{itemize}

\textbf{Repetition penalty} เปลี่ยน output เกือบทุกรายการ (หน้าเต็ม BQ ที่ไม่วนซ้ำไม่มีหน้าใดเหมือน greedy เลย) และทำให้ F1 ของหน้าที่ไม่วนซ้ำลดลง 1.1--1.3 จุด ในงานอ่านข้อความสั้น (BQ) อัตราผิดของวรรณยุกต์เพิ่มจาก 17.1\% เป็น 22.6\% ส่วนบนทุกหน้า ผลแยกจากศูนย์ไม่ได้ (+0.89 [$-$2.70, +4.81]) ข้อความไทยมีพยางค์และวรรณยุกต์ซ้ำกันเป็นปกติ ซึ่ง penalty ทั้งหน้าอาจกดไว้ แต่เรายังไม่ได้ทดสอบคำอธิบายนี้

\textbf{n-gram blocking} ปลอดภัยเมื่อไม่มีการวนซ้ำ (output ที่ไม่วนซ้ำไม่เปลี่ยน 92--100\%, $\Delta$F1 $\le$ 0.05) และหยุดการวนซ้ำได้ 6 จาก 11 รายการ ในรายการที่หยุดไม่ได้ โมเดลหนีไปวนแบบใกล้เคียงของเดิม เช่น ชื่อซอยที่เพี้ยนไปเป็นชื่อซอยคล้ายกันสามชื่อ ข้อความเหล่านี้มี mark เพิ่ม ทำให้ mark ที่เขียนเกินสูงขึ้น และ F1 บนหน้าเต็มต่ำลง 0.68 (BQ) เราตีความว่าการวนซ้ำเป็นสถานะดึงดูดของ decoder การห้ามสำเนาที่ซ้ำตรงตัวจึงย้ายโมเดลไปอยู่ในสถานะข้างเคียง ซึ่งเป็นการตีความ ไม่ใช่กลไกที่ทดสอบแล้ว

\textbf{หยุดเมื่อพบการวนซ้ำ} ไม่เปลี่ยน output ที่ไม่วนซ้ำเลย (ไม่มี output ที่ไม่วนซ้ำถูกเปลี่ยนในเซลล์ใด) และเพิ่ม mark F1 บนหน้าเต็ม 0.84 (BQ) และ 0.67 (TC) และเพิ่ม F1 งานอ่านข้อความสั้น 3.30 และ 2.39 ทั้งยังลด token ที่สร้างลง 11.2\% recall ลดลงไม่เกิน 0.16 จุด เพราะการหยุดไม่เคยกู้ข้อความที่การวนซ้ำทำให้ข้ามไป กฎนี้เขียนหลังจากเห็นผลการเปรียบเทียบก่อนหน้า และในแต่ละเซลล์มี output ที่วนซ้ำเพียงหนึ่งถึงสี่รายการ ช่วงความเชื่อมั่นทุกช่วงจึงรวมศูนย์ไว้

\subsection{The Stop on a Second Model}

\subsection{Subtracting the Language Prior Removes Correct Marks}
ในการทดสอบแบบเลือกตอบบังคับ การหักคะแนนแบบไม่มีภาพด้วยน้ำหนัก $\lambda$ ทำให้ความแม่นยำของวรรณยุกต์ของ Typhoon ลดจาก 99.7\% เป็น 97.3\% ที่ $\lambda=0.5$ และเหลือ 42.3\% ที่ $\lambda=1$ (รูปที่~\ref{fig:prior} ด้านขวา) ส่วนโมเดลตั้งต้นลดเหลือ 84.7\% ที่ 0.5 ในการ generate จริง บนกลุ่มย่อย 24 ข้อ contrast แบบ M3ID-form ของเราหยุดการวนซ้ำของโมเดลตั้งต้นได้ (character error rate จาก 1.12 เหลือ 0.21) แต่อัตราผิดของวรรณยุกต์ในข้อที่เก็บไว้เพิ่มจาก 3.7\% เป็น 7.6\% ส่วนใหญ่เพราะวรรณยุกต์ถูกลบ (21 เป็น 55 ใน 12 ข้อ) ส่วน Typhoon เปลี่ยนเพียงเล็กน้อยและกระจุกอยู่ในไม่กี่ข้อ ผลทั้งสองชี้ไปทางเดียวกัน คือความรู้ภาษาเกี่ยวกับวรรณยุกต์ถูกอยู่แล้ว การหักออกจึงลบวรรณยุกต์ที่ถูกไปด้วย

\subsection{Speed}
Speculative decoding แบบ prompt lookup ทำให้ Typhoon เร็วขึ้น 1.14--1.15 เท่า (โมเดลตั้งต้น 1.16--1.21 เท่า) บนหน้าที่ไม่เสื่อมเป็นการวนซ้ำ โดย output เหมือนเดิมยกเว้นจุดที่คะแนนสองตัวเลือกเกือบเท่ากันใน fp16 (88--93\% ของทุกข้อเหมือนเดิม) ตัวอ้างอิง greedy ให้ output ตรงกับ output หลักของเราทุกตัวอักษรในทั้ง 177 ข้อที่จับเวลา \todo{ความเร็วเมื่อใช้การหยุดร่วมกับ speculative decoding}

\section{Discussion and Limitations}
\textbf{สิ่งที่สรุปได้} สำหรับโมเดลที่ศึกษา ความผิดของ mark ในโมเดล OCR ภาษาไทยที่เก่งอยู่แล้วส่วนใหญ่เกิดก่อนถึงตัว mark ได้แก่ บรรทัดที่ไม่ได้อ่าน ข้อความที่ขาดเป็นช่วง และการวนซ้ำ เมื่อได้บริบทที่ถูก วรรณยุกต์เกือบแน่นอนอยู่แล้ว และวิธีที่หักความรู้ภาษาออกต้องแลกด้วยวรรณยุกต์ ส่วนวิธีที่ถูกและปลอดภัยในการจัดการการวนซ้ำคือหยุดมัน

\textbf{ข้อจำกัด} (1) benchmark เดียวและสองงาน (2) ทุกผลอยู่บนชุด calibration และกฎการหยุด คะแนนแบบกันการวนซ้ำ และการให้คะแนนถูกเขียนหลังจากเห็นข้อมูล ส่วนชุด locked ยังไม่ถูกเปิด \todo{รอดำเนินการ} (3) โมเดลถูกเทียบตามที่เผยแพร่ งบ visual token ไม่เท่ากัน และ Paddle กับ Wayu เป็นตัวอ่านทีละกรอบที่นำมาอ่านทั้งหน้านอกเหนือจากที่ออกแบบ (4) output ที่วนซ้ำมีน้อย ช่วงความเชื่อมั่นของ Typhoon ส่วนใหญ่จึงรวมศูนย์ไว้ ข้อสรุปจึงเป็นเรื่องกลไก ไม่ใช่อัตรา (5) การจัดสาเหตุเป็นแบบอัตโนมัติ (6) การทดสอบแบบเลือกตอบบังคับใช้บริบทที่ถูกต้อง (7) contrast ที่เราใช้เป็นการเขียนใหม่และทดสอบบน 24 ข้อ (8) เงื่อนไขการใช้ Typhoon: เราใช้ revision ที่เผยแพร่ภายใต้ Apache-2.0 อย่างเดียว ขณะที่เงื่อนไขปัจจุบันของผู้พัฒนาขอให้ได้รับความยินยอมเป็นลายลักษณ์อักษรก่อนนำไปเทียบประสิทธิภาพ

\section{Conclusion}
เครื่องหมายสระและวรรณยุกต์ไม่ใช่จุดที่ OCR แบบเปิดที่เก่งที่สุดพลาด มันพลาดก่อนหน้านั้น คือไม่ได้อ่าน หาไม่เจอ หรือวนซ้ำ การหยุดเมื่อตรวจพบการวนซ้ำเป็นขั้นตอนที่ปลอดภัย ไม่ต้อง train เพิ่ม และได้ผลที่วัดได้ ส่วนการหักความรู้ภาษาออกไม่ใช่ \todo{ข้อสรุปสุดท้ายรอผลการทดลองที่เหลือ}

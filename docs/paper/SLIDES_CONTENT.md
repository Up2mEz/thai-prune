# เนื้อหาสไลด์: วรรณยุกต์เป็นจุดอ่อนของ OCR ภาษาไทยแบบเปิดจริงหรือ

ชุดนี้ทำตามต้นฉบับ paper (`docs/paper/ieee/v2/`, ชื่อเรื่อง *Are Tone Marks the Weak Point of Open Thai OCR? A Locked-Split Study of Eight Models*) และ `docs/CLAIMS.md` ข้อ 12–17 เป็นเด็คใหม่ ไม่ใช่การแก้เด็คเดิมใน `docs/presentdesign.md` (เด็คเดิมเล่าเรื่อง Typhoon อย่างเดียว ก่อนมีผล 8 โมเดล)

เอกสารนี้บอกว่าแต่ละหน้าควรพูดอะไร ใส่ตัวเลขอะไร และควรมีภาพแบบไหน ส่วนภาพให้ทำเองตามคำอธิบาย ไม่ประกอบ SVG ด้วยมือ

**สมมติฐานที่ผมตั้งเอง (แก้ได้):** ใช้พรีเซนต์ 15–20 นาทีต่ออาจารย์หรือในชั้นเรียน จึงทำ **15 หน้าหลัก** (ราว 1–1.5 นาทีต่อหน้า) บวก **หน้าสำรอง 5 หน้า** และชุดคำถามที่อาจโดนถาม ถ้าเวลาสั้นกว่านี้ ดูหัวข้อ "ถ้าเวลาไม่พอ" ท้ายเอกสาร

ทุกหน้าใช้โครงเดียวกัน:

- **คำถาม:** หน้านี้ตอบคำถามอะไร
- **ทำอะไร:** ทดลองอย่างไร (เล่าแบบคนไม่เคยเห็นงานก็เข้าใจ)
- **ผล:** ตัวเลขที่ต้องใส่
- **แปลว่า:** ประโยคที่อยากให้ผู้ฟังจำ
- **ภาพ:** ควรวาดอะไร
- **ต้องบอกด้วย:** ข้อจำกัดของหน้านั้น
- **พูด:** ประโยคเปิดและปิดที่ใช้ได้เลย

---

## เรื่องที่เล่าทั้งเด็ค (เส้นเรื่องเดียว)

> วรรณยุกต์และสระของไทยตัวเล็กและเปลี่ยนความหมายคำได้ คนจึงสงสัยว่าเป็นจุดอ่อนของ OCR ภาษาไทย เราวัดใน 8 โมเดลแบบเปิดแล้วพบว่า **ส่วนใหญ่ไม่ใช่** mark ที่เสียไปส่วนใหญ่ไม่ได้ถูกอ่านผิด แต่ **ไม่ปรากฏใน output เลย** (ข้ามบรรทัด หาไม่เจอ หรือวนซ้ำ) เมื่อให้บริบทถูก โมเดลเลือกวรรณยุกต์ถูกราว 99% ส่วนวิธีที่ช่วยได้ง่ายที่สุดคือหยุดเมื่อวนซ้ำ ซึ่งยืนยันบนชุดข้อมูลที่เปิดอ่านครั้งเดียว

โครงเรื่อง: **ทำไมถาม → วัดอย่างไร → mark หายที่ไหน → โมเดลรู้วรรณยุกต์ไหม → แก้ได้ด้วยอะไร → ยืนยันบนชุดที่เก็บไว้ → ข้อจำกัด → สรุป**

## ก่อนเริ่ม: ตกลงคำที่ใช้ทั้ง deck

บนสไลด์ใช้แค่คำเหล่านี้ และอธิบายครั้งแรกที่พูดถึง

| คำ | ความหมาย |
|---|---|
| **mark** | สระบน (ิ ี ึ ื ั ็), สระล่าง (ุ ู) และวรรณยุกต์ (่ ้ ๊ ๋) |
| **คะแนน mark** | เอา mark ทุกตัวในเฉลยมาเทียบกับที่โมเดลเขียน หักทั้งตัวที่หายและตัวที่เขียนเกิน เต็ม 100 (ชื่อทางเทคนิคคือ mark F1) ไม่สนลำดับบรรทัด |
| **ไม่ปรากฏใน output** | บรรทัดหรือช่วงข้อความในเฉลยที่หาไม่เจอในสิ่งที่โมเดลเขียน **ไม่ได้แปลว่าโมเดลมองไม่เห็น** (อาจเห็นแล้วไม่เขียน) |
| **วนซ้ำ (loop)** | โมเดลเขียนหน่วยเดิมซ้ำไม่หยุดจนถึงความยาวสูงสุด |
| **หยุดเมื่อวนซ้ำ (stop)** | ตัด output ตั้งแต่สำเนาแรกของหน่วยที่ซ้ำ 8 ครั้ง (หรือ 6 ครั้งถ้าหน่วยยาว 50 ตัวอักษรขึ้นไป) ไม่ต้อง train เพิ่ม |
| **ชุด calibration** | 178 ข้อ (อ่านทั้งหน้า 69, อ่านข้อความสั้น 109) ใช้พัฒนาวิธีและตัดสินใจออกแบบ |
| **ชุด locked** | 352 ข้อ (อ่านทั้งหน้า 128, อ่านข้อความสั้น 224) ไม่แตะจนกฎทุกข้อนิ่ง แล้วเปิดอ่าน **ครั้งเดียว** ตามที่ลงทะเบียนไว้ล่วงหน้า |
| **forced choice** | ให้ข้อความที่ถูกต้องจนถึงตำแหน่ง mark แล้วให้โมเดลให้คะแนนตัวเลือก mark ที่เป็นไปได้ ไม่ใช่การเขียนเอง |
| **Typhoon / Pathumma** | Thai fine-tune สองตัวจาก Qwen3-VL-2B (Typhoon OCR 1.5, Pathumma-llm-vision 3.0) |
| **โมเดลทั่วไป** | Qwen3-VL-2B (ตั้งต้น), Qwen3-VL-4B, SEA-LION v4 4B |

**ป้ายเล็กมุมล่างทุกหน้าที่มีผล (สองแบบ):**
- ผลบน calibration: "ผลเบื้องต้น · ชุด calibration (ใช้ออกแบบวิธี)"
- ผลบน locked: "ผลเบื้องต้น · ชุด locked อ่านครั้งเดียว · ไม่ใช่หลักฐานผ่าน gate"

**ตัวเลขที่ต้องอ้างให้ถูก:** ถ้ามีทั้งตัวเลข calibration และ locked ให้ใช้ locked เป็นตัวเลขหลัก (ผู้อนุมัติ `CLAIMS.md` ระบุไว้)

## หน้า 1: วรรณยุกต์เป็นจุดอ่อนของ OCR ภาษาไทยจริงหรือ

- **ภาพ:** ชื่อเรื่อง (EN) + ชื่อไทย รายชื่อผู้เขียน 3 คน และสังกัด ใต้ชื่อมีประโยคเดียว: "คำตอบสั้นๆ: ส่วนใหญ่ไม่ใช่" พร้อมตัวเลขเล็ก "8 โมเดล · ชุดข้อมูลที่เปิดอ่านครั้งเดียว"
- **พูด:** ทำร่วมกับเพื่อน (PELY334) ที่รันการทดลองบน GPU ส่วนผมวางการวัดและเขียน paper เปิดด้วยคำตอบก่อนเลย แล้วเล่าว่าได้คำตอบนี้มาอย่างไร

## หน้า 2: ทำไมต้องถาม

- **คำถาม:** ทำไม mark ถึงน่าสงสัย และมีกี่คำอธิบายที่เป็นไปได้
- **ผล / เนื้อหา:**
  - mark ตัวเดียวเปลี่ยนความหมายและเสียง: **ข่าว** กับ **ข้าว**
  - ตัวชี้วัด OCR ไทยที่ใช้อยู่ (n-gram, normalized edit distance, CER) บอกไม่ได้ว่า mark เป็นปัญหาหรือเปล่า และลงโทษโมเดลที่อ่านคอลัมน์สลับลำดับด้วย
  - เมื่อโมเดลทำ mark ผิด มี 3 คำอธิบาย แต่ละข้อต้องแก้ต่างกัน

| คำอธิบาย | ถ้าจริง ควรแก้ด้วย |
|---|---|
| หลักฐานในภาพของ mark ขนาดเล็กอ่อน | อ่านซ้ำ หรือขยายภาพ |
| ความรู้ภาษาของโมเดลทับหลักฐานในภาพ | หักความรู้ภาษาออก (contrastive decoding) |
| mark **ไม่ปรากฏใน output เลย** (ข้ามบรรทัด หาไม่เจอ วนซ้ำ) | แก้วิธี decode หรือการหาตำแหน่งข้อความ |

- **แปลว่า:** ก่อนจะแก้อะไร ต้องรู้ก่อนว่า mark หายด้วยเหตุผลข้อไหน
- **ภาพ:** การ์ดตัวอักษร ข่าว / ข้าว ขนาดใหญ่ด้านซ้าย ตารางสามแถวด้านขวา (ทำในโปรแกรมสไลด์ได้)
- **ต้องบอกด้วย:** จาก output อย่างเดียวบอกไม่ได้ว่าในโมเดลเกิดอะไรขึ้น เราจึงใช้คำว่า "ไม่ปรากฏใน output" ไม่ใช่ "โมเดลมองไม่เห็น"
- **พูด:** "วันนี้เราตอบคำถามเดียว: mark เป็นจุดอ่อนจริงไหม และถ้าไม่ใช่ จุดอ่อนอยู่ที่ไหน"

## หน้า 3: ออกแบบงานให้ผลน่าเชื่อถือ

- **คำถาม:** เราทำอย่างไรไม่ให้ "ปรับวิธีจนผลดี" ปนกับ "ผลที่ยืนยันแล้ว"
- **ทำอะไร:**
  1. พัฒนาวิธีทั้งหมดบน **ชุด calibration** (178 ข้อ)
  2. **ลงทะเบียนการทดสอบและวิธีอ่านผลไว้ก่อน** (S1, S2, R1) ก่อนเห็นผลของชุดที่เก็บไว้
  3. เปิด **ชุด locked** (352 ข้อ) อ่านครั้งเดียว ใช้ 8 โมเดล
- **ผล:** 8 โมเดล = Typhoon OCR 1.5, Pathumma 3.0, Wayu (wayu-paxa-ocr-zero), PaddleOCR-VL-1.6, Qwen3-VL-2B, Qwen3-VL-4B, SEA-LION v4 4B, DeepSeek-OCR-2 ใช้ GPU T4 รวม 26.5 ชั่วโมงบนชุด locked
- **แปลว่า:** ตัวเลขที่ควรเชื่อที่สุดคือตัวเลขจากชุดที่เก็บไว้
- **ภาพ:** เส้นเวลาสามช่อง ซ้ายไปขวา: "พัฒนา (calibration)" → "ลงทะเบียนล่วงหน้า" → "เปิดอ่านครั้งเดียว (locked)" ใต้ช่องที่สามมีตัวเลข 352 ข้อ ด้านล่างเป็นแถบโลโก้ชื่อโมเดล 8 ตัวเรียงเป็นตาราง 4×2 (ไม่ต้องใส่ผล)
- **ต้องบอกด้วย:** ชุด locked ในรอบนี้มี 352 ข้อ ไม่ใช่ราว 415 ที่ registration คาดไว้ ยังไม่ทราบสาเหตุ จึงบอกเป็นจำนวนข้อเท่านั้น และผลนี้ยังเป็นผลเบื้องต้น ไม่ได้เปิดหรือผ่าน gate ใด
- **พูด:** "ผมแยกชัดว่าอะไรคือที่ใช้ปรับ อะไรคือที่ใช้ตัดสิน"

## หน้า 4: วัด mark โดยไม่ลงโทษลำดับการอ่าน

- **คำถาม:** วัด mark อย่างไรให้เป็นธรรมกับโมเดลที่อ่านคอลัมน์สลับ
- **ทำอะไร:** ให้คะแนน mark ทีละบรรทัดของเฉลย ไม่ว่าบรรทัดนั้นจะอยู่ตรงไหนของ output ข้อความที่เขียนเกินถูกหัก และ **สำเนาที่เกิดจากการวนซ้ำไม่ได้คะแนน** (แบบ repeat-aware)
- **ผล:**
  - Typhoon: คะแนน mark แบบไม่สนลำดับ **94.9** แบบบังคับลำดับ 93.1 ต่างกันราว 2 คะแนนจากลำดับอย่างเดียว ไม่ใช่การอ่านผิด
  - โมเดลตั้งต้น (Qwen3-VL-2B): 41.0 แบบธรรมดา และ **34.4** เมื่อไม่ให้คะแนนสำเนาวนซ้ำ (ราวหนึ่งในหกของ mark ที่ได้คะแนนมาจากสำเนาวนซ้ำ)
  - ตรวจแล้ว: ทั้ง 126 ช่วงที่ตัดออกชนขีดจำกัดความยาวทั้งหมด ไม่มีข้อความปกติถูกตัด
- **แปลว่า:** ตัวชี้วัดนี้ไม่โกงให้โมเดลที่วนซ้ำ และไม่ลงโทษโมเดลที่อ่านถูกแต่สลับลำดับ
- **ภาพ:** ซ้าย: ตัวอย่างข้อความสองบรรทัด A แล้ว B ในเฉลย แต่โมเดลเขียน B แล้ว A ใต้ภาพ "วิธีเดิม: ผิดเยอะ / วิธีใหม่: ถูกครบ" ขวา: การ์ดตัวเลข 2 ใบ "94.9 vs 93.1 (Typhoon)" และ "41.0 → 34.4 (โมเดลตั้งต้น)"
- **ต้องบอกด้วย:** แบบ repeat-aware เพิ่มทีหลังเพราะเพื่อนพบว่า alignment จับสำเนาซ้ำ 434 ชุดไปคู่กับพยางค์ทั่วไปในเฉลย (ผลเบื้องต้นจากชุด calibration)
- **พูด:** "ตัวชี้วัดนี้เป็นเครื่องมือ ไม่ใช่ผลหลัก ผลหลักอยู่หน้าถัดไป"

## หน้า 5: ภาพรวมโมเดลบนชุด calibration

- **คำถาม:** โมเดลที่วัดอยู่ตรงไหนของกันและกัน
- **ผล (คะแนน mark, อ่านทั้งหน้า / อ่านข้อความสั้น):**

| โมเดล | อ่านทั้งหน้า | อ่านข้อความสั้น |
|---|---|---|
| Typhoon OCR 1.5 | **94.9** | **81.7** |
| Pathumma 3.0 | 89.8 | 77.6 |
| Wayu | 65.2 | 46.0 |
| PaddleOCR-VL-1.6 | 53.3 | 47.9 |
| Qwen3-VL-4B | 45.9 | 23.5 |
| Qwen3-VL-2B (ตั้งต้น) | 41.0 | 24.3 |

  - Pathumma ต่างจาก Typhoon −5.1 (ช่วง −14.3 ถึง +1.6) บนหน้าเต็ม ช่วงคร่อม 0 จึงบอกไม่ได้ว่าตัวใดดีกว่า
  - ทั้งสองสูงกว่าโมเดลตั้งต้นมาก (+48.9 และ +53.3)
  - เพิ่มขนาดโมเดลตั้งต้นเป็นสองเท่า (4B) เปลี่ยนคะแนนเพียง +5.0 (ช่วง −4.0 ถึง +14.1)
- **แปลว่า:** Thai fine-tune สองตัวห่างโมเดลทั่วไปมาก แต่แยกกันเองไม่ออก
- **ภาพ:** แท่งแนวนอน 6 แท่ง สองแผง (หน้าเต็ม / ข้อความสั้น) เทา = โมเดลทั่วไป น้ำเงิน = Thai fine-tune ใส่ตัวเลขบนแท่ง ใช้ Plotly
- **ต้องบอกด้วย (สำคัญ):** เทียบโมเดลตามที่เผยแพร่ visual token ไม่เท่ากัน และ **ข้อมูลอาจซ้อนกับ benchmark**: Typhoon มาจากกลุ่มที่ทำ ThaiOCRBench และ Pathumma ไม่ระบุข้อมูลฝึก 377K ตัวอย่าง จึงเรียก Typhoon ว่า "แข็งที่สุดที่วัด ใกล้เคียง Pathumma" เท่านั้น ห้ามพูดว่า "ดีที่สุด"
- **พูด:** "ถ้าใครถามว่าตัวไหนดีที่สุด คำตอบที่ปลอดภัยคือ Thai fine-tune สองตัว แยกกันไม่ออก"

## หน้า 6: mark หายไปที่ไหน (ชุด calibration)

- **คำถาม:** ใน mark ที่เสียไป เสียเพราะอะไร
- **ทำอะไร:** จัดสาเหตุของแต่ละ mark ที่เสียโดยอัตโนมัติเป็น 4 แบบ: อ่านถูกแต่คนละลำดับ / ทั้งบรรทัดไม่ปรากฏใน output / ขาดเป็นช่วงในบรรทัดที่เก็บไว้ / อ่านผิดตัว (ตัดที่การวนซ้ำครั้งแรกก่อน เพื่อให้ alignment เชื่อถือได้)
- **ผล (สัดส่วนของ mark ในเฉลยทั้งหมด, อ่านทั้งหน้า %):**

| โมเดล | คนละลำดับ | ทั้งบรรทัดหาย | ขาดเป็นช่วง | อ่านผิดตัว |
|---|---|---|---|---|
| Typhoon | 1.6 | 2.7 | 0.5 | 1.3 |
| Pathumma | 0.9 | 6.9 | 2.4 | 2.1 |
| Wayu | 0.4 | 20.6 | 8.3 | 9.0 |
| PaddleOCR-VL | 0.0 | 37.6 | 6.3 | 11.5 |
| Qwen3-VL-4B | 0.1 | 24.8 | 6.6 | 9.7 |
| Qwen3-VL-2B | 0.2 | 33.4 | 5.0 | 7.6 |

  - "ไม่ปรากฏ" (ทั้งบรรทัด + ขาดเป็นช่วง) กิน 3.2% (Typhoon), 9.3% (Pathumma) และ 29–44% (สี่ตัวที่เหลือ)
  - อ่าน mark ผิดทั้งที่พยัญชนะถูกกิน 0.4%, 0.8% และ 2.7–4.3% ตามลำดับ → ข้อความที่ไม่ปรากฏเสีย mark มากกว่า **7–12 เท่า** ในทุกโมเดล
  - ใน Typhoon บรรทัดที่หายส่วนใหญ่คือข้อความใน infographic กราฟ โฆษณาแทรก และชื่อเรื่อง ซึ่งโมเดลเขียนเป็นตัวแทนภาพ
- **แปลว่า:** จุดอ่อนไม่ใช่ตัว mark แต่คือข้อความที่ไม่ถูกเขียนออกมา
- **ภาพ:** แท่งแนวนอนแบบซ้อน (stacked) 6 แท่ง สี 4 แบบตามสาเหตุ ส้มแดง = ทั้งบรรทัดหาย ส้มอ่อน = ขาดเป็นช่วง ม่วงชมพู = อ่านผิด เทาอ่อน = คนละลำดับ (ไม่ใช่ความผิดจริง) ใส่ยอดรวมท้ายแท่งโดยไม่รวมส่วนสีเทา ใช้ Plotly
- **ต้องบอกด้วย:** การจัดสาเหตุเป็นแบบอัตโนมัติ ตรวจภาพเอกสารเฉพาะ 6 หน้าที่มี mark หายมากสุดของ Typhoon และสำหรับโมเดลที่วนซ้ำ บรรทัดหลังการวนซ้ำนับเป็น "หาย" แยกไม่ได้ว่าหายเพราะวนซ้ำหรือเพราะโมเดลไม่อ่านอยู่แล้ว
- **พูด:** "เห็นสีส้มกับสีม่วงไหม ส้มคือข้อความไม่มา ม่วงคืออ่านผิด ส้มใหญ่กว่าม่วงทุกโมเดล"

## หน้า 7: ยืนยันบนชุด locked: ข้อความที่หายเสียมากกว่า mark ที่อ่านผิด

- **คำถาม:** ข้อสรุปหน้า 6 ยังจริงไหมกับข้อมูลที่ไม่เคยเห็น
- **ทำอะไร:** ลงทะเบียนการทดสอบ R1 ไว้ก่อน: อ่านทั้งหน้า (ข้อความที่หาย + ช่วงที่ขาด) ÷ (mark ที่อ่านผิดทั้งที่พยัญชนะถูก) ต้องมากกว่า 3 โดยขอบล่างของช่วงความเชื่อมั่น 95% ต้องสูงกว่า 3
- **ผล (อัตราส่วน [ช่วง 95%]) ผ่านทั้ง 8 โมเดล:**

| โมเดล | อัตราส่วน |
|---|---|
| Pathumma | 15.8 [7.5, 32.0] |
| Wayu | 10.8 [7.1, 16.0] |
| Typhoon | 8.2 [5.5, 14.3] |
| SEA-LION v4 4B | 7.8 [5.6, 10.4] |
| DeepSeek-OCR-2 (fp16) | 7.8 [5.8, 10.5] |
| Qwen3-VL-2B | 7.8 [5.0, 11.7] |
| Qwen3-VL-4B | 6.1 [3.7, 9.2] |
| PaddleOCR-VL-1.6 | **4.7 [3.2, 6.7]** |

- **แปลว่า:** ใน 8 โมเดลบน benchmark นี้ mark เสียเพราะข้อความไม่ปรากฏ มากกว่าเพราะอ่านผิดอย่างน้อย 4.7 เท่า
- **ภาพ:** กราฟจุดพร้อมช่วงความเชื่อมั่น (forest plot) แนวนอน 8 แถว แกน x เริ่ม 0 เส้นประตั้งตรงเลข 3 (เกณฑ์) ทุกช่วงอยู่ขวาของเส้นประ PaddleOCR-VL ใกล้เส้นที่สุด ไฮไลต์ ใช้ Plotly
- **ต้องบอกด้วย:** PaddleOCR-VL ผ่านเฉียดๆ (ขอบล่าง 3.2) และข้อนี้เป็นข้อความเกี่ยวกับ 8 โมเดลนี้บน benchmark เดียว ไม่ขยายไปโมเดลอื่น
- **พูด:** "ลงทะเบียนเกณฑ์ไว้ก่อนเห็นผล และผ่านครบทุกตัว แต่ผ่านเฉียดสุดคือ Paddle"

## หน้า 8: ถ้าให้บริบทถูก โมเดลเลือกวรรณยุกต์ถูกเกือบทุกครั้ง

- **คำถาม:** โมเดลรู้ว่าวรรณยุกต์ที่ถูกคืออะไรไหม
- **ทำอะไร:** forced choice: ป้อนข้อความที่ถูกต้องจนถึงตำแหน่ง mark แล้วให้โมเดลให้คะแนนตัวเลือก mark ที่เป็นไปได้ทั้งแบบมีภาพและไม่มีภาพ (fp32, อ่านทั้งหน้า, ชุด calibration)
- **ผล (ความแม่นยำวรรณยุกต์ %, มีภาพ / ไม่มีภาพ):**

| โมเดล | มีภาพ | ไม่มีภาพ | ภาพช่วย |
|---|---|---|---|
| Typhoon | 99.7 | 98.8 | +0.9 |
| Pathumma | 99.7 | 98.7 | +1.0 |
| Qwen3-VL-4B | 98.7 | 99.1 | −0.5 |
| Qwen3-VL-2B | 98.1 | 98.9 | −0.8 |

- **แปลว่า:** โมเดลรู้วรรณยุกต์ที่ถูกอยู่แล้ว ภาพเพิ่มให้แค่ราว 1 จุด (หรือไม่เพิ่มเลย) ความแม่นยำนี้มาจากความรู้ภาษาเป็นหลัก ไม่ใช่การมองเห็น mark ทีละตัว
- **ภาพ:** แท่งแนวนอนแสดง "ภาพช่วยเพิ่ม (จุด)" 4 แท่ง มีเส้น 0 ตรงกลาง Thai fine-tune สีน้ำเงิน โมเดลทั่วไปสีเทา ใส่ตัวเลขบนแท่ง ใช้ Plotly
- **ต้องบอกด้วย:** นี่ไม่ใช่การเขียนจริง เพราะโมเดลได้ข้อความก่อนหน้าที่ถูกต้อง ซึ่งโมเดลที่วนซ้ำหรือข้ามบรรทัดไม่มีตอนเขียนเอง ผลบน calibration เท่านั้น
- **พูด:** "ถ้า mark เป็นจุดอ่อนเรื่องการมองเห็น ภาพควรช่วยมาก แต่ภาพช่วยแค่จุดเดียว"

## หน้า 9: ข้อยกเว้น: Qwen3-VL-4B รู้ แต่เขียนเองผิดบ้าง

- **คำถาม:** รู้ mark ที่ถูก แปลว่าเขียนถูกตอนเขียนเองด้วยไหม
- **ผล (ตำแหน่งที่พยัญชนะฐานอ่านถูก, วรรณยุกต์อ่านทั้งหน้า %, เขียนเอง / การทดสอบที่ตำแหน่งเดียวกัน):**

| โมเดล | เขียนเอง | การทดสอบ (รู้) | ช่องว่าง |
|---|---|---|---|
| Pathumma | 99.4 | 99.8 | 0.4 |
| Qwen3-VL-4B | **91.3** | 99.1 | **7.8** |

  - Qwen3-VL-4B อ่านวรรณยุกต์ผิดราว 1 ตัวในทุก 11 ตัว ระหว่างเขียนหน้าเอง ทั้งที่การทดสอบแสดงว่ารู้ตัวที่ถูก
  - บน calibration ข้อความที่หายยังเสีย mark มากกว่าการอ่านผิดถึง 7.3 เท่าสำหรับโมเดลนี้ ทิศทางจึงยังเหมือนเดิม
- **แปลว่า:** ข้อค้นพบ "ส่วนใหญ่หายไปจาก output" เป็นจริงกับทั้ง 8 โมเดล แต่ "แทบไม่เคยอ่านผิด" จริงเฉพาะกับ Thai fine-tune สองตัว
- **ภาพ:** แท่งคู่ 2 กลุ่ม (Pathumma, Qwen3-VL-4B) แต่ละกลุ่มมี "เขียนเอง" (สีเต็ม) กับ "การทดสอบ" (สีโปร่ง) แกนตั้งเริ่ม 85 เขียนกำกับใต้กราฟว่า "แกนเริ่มที่ 85%" ใส่ตัวเลขบนแท่ง ใช้ Plotly
- **ต้องบอกด้วย:** เป็นผลบน calibration และโมเดลเดียว ยังไม่ได้ทดสอบสาเหตุว่าทำไม 4B อ่านผิดตอนเขียน ข้อความ "ไม่ใช่ mark" ในชื่อเรื่องจึงต้องบอกว่า "ส่วนใหญ่"
- **พูด:** "นี่คือข้อยกเว้นที่ผมไม่ซ่อน และเป็นเหตุผลที่ชื่อเรื่องถามว่าจุดอ่อนไหม แทนที่จะบอกว่าไม่ใช่"

## หน้า 10: การหักความรู้ภาษาออกไม่ใช่ทางแก้

- **คำถาม:** ถ้าคิดว่าความรู้ภาษาทับภาพ การหักมันออกช่วยไหม
- **ผล:**
  - forced choice (Typhoon, อ่านทั้งหน้า): หักน้ำหนัก 0 / 0.5 / 1 ได้ 99.7 / **97.3** / **42.3** (โมเดลตั้งต้นเหลือ 84.7 ที่ 0.5, Pathumma 94.8, Qwen3-VL-4B 88.7)
  - ตอน generate จริง (24 ข้อ): contrast แบบ M3ID-form หยุดการวนซ้ำของโมเดลตั้งต้นได้ (CER 1.12 → 0.21) แต่ผิดวรรณยุกต์เพิ่มจาก 3.7% เป็น 7.6% เพราะลบวรรณยุกต์ (21 → 55 ตัวใน 12 ข้อ)
  - repetition penalty 1.1 (ค่าในแพ็กเกจของ Typhoon เอง): คะแนนของหน้าที่ไม่วนซ้ำลดลง 1.1–1.3 และผิดวรรณยุกต์ในงานข้อความสั้นเพิ่มจาก 17.1% เป็น 22.6%
- **แปลว่า:** ความรู้ภาษาของวรรณยุกต์ถูกอยู่แล้ว ตัดมันออกก็ตัดวรรณยุกต์ที่ถูกไปด้วย
- **ภาพ:** กราฟเส้นมีจุด 3 จุด แกน x = น้ำหนักที่หัก (0, 0.5, 1) แกน y = ความแม่นยำ (0–100) ใส่ตัวเลขที่จุด เส้นสีน้ำเงิน ใช้ Plotly
- **ต้องบอกด้วย:** วิธีของเราเป็นการเขียนใหม่ จึงเรียก "M3ID-form" ไม่ใช่ M3ID ทดสอบบน 24 ข้อเท่านั้น
- **พูด:** "ถ้าความรู้ภาษาเป็นศัตรู การตัดมันควรช่วย แต่มันพังที่ 42%"

## หน้า 11: การวนซ้ำพบน้อยแต่เสียหายมาก

- **คำถาม:** เมื่อ mark ส่วนใหญ่เสียเพราะไม่ปรากฏ แล้วการวนซ้ำเกี่ยวข้องแค่ไหน
- **ผล (Typhoon, ชุด calibration):**
  - จาก output 356 รายการ มีวนซ้ำ **11** รายการ แต่หน้าที่วนซ้ำเพียง 2–5 หน้าต่อเซลล์ถือ mark ที่เขียนเกินรวมกัน **68–76%**
  - ถ้าไม่มีหน้าเหล่านั้น คะแนนอ่านทั้งหน้าจะเป็น 97.4 แทน 94.9 (เป็นเพดาน ไม่ใช่ผลของวิธีใด)
  - เทียบ 3 วิธีจัดการ (Δ คะแนนอ่านทั้งหน้า, ทุกหน้า / หน้าที่ไม่วนซ้ำ):

| วิธี | ทุกหน้า | หน้าไม่วนซ้ำ |
|---|---|---|
| repetition penalty 1.1 | +0.89 (ช่วงคร่อม 0) | **−1.30** |
| ห้ามซ้ำ n-gram (30-gram ใน 90 token) | −0.68 | −0.02 |
| **หยุดเมื่อวนซ้ำ** | **+0.84** | **0.00** |

  - n-gram blocking หยุดการวนซ้ำได้ 6 จาก 11 ครั้ง ที่เหลือโมเดลหนีไปวนแบบใกล้เคียง (เช่น ชื่อซอยเพี้ยนไปสามชื่อ)
  - การหยุดประหยัด token 11.2% และไม่เปลี่ยน output ที่ไม่วนซ้ำเลย
- **แปลว่า:** วิธีเดียวที่ไม่ทำร้ายหน้าที่ปกติคือหยุดเมื่อวนซ้ำ
- **ภาพ:** แท่งแนวนอน 3 กลุ่ม กลุ่มละ 2 แท่ง (ทุกหน้า สีเต็ม / หน้าไม่วนซ้ำ สีโปร่ง) มีเส้น 0 ค่าบวกเขียวอมฟ้า ค่าลบส้มแดง ใส่ช่วง 95% บนแท่ง "ทุกหน้า" ใช้ Plotly ตัวเลขตัวใหญ่มุมขวาบน: "11 / 356"
- **ต้องบอกด้วย:** Typhoon วนซ้ำน้อย ทุกช่วงความเชื่อมั่นจึงคร่อม 0 กฎการหยุดเขียนหลังเห็นข้อมูล calibration ทดสอบเฉพาะ Typhoon ในหน้านี้
- **พูด:** "สองวิธีแรกสร้างปัญหาใหม่ วิธีที่สามไม่แตะอะไรที่ไม่เสียอยู่แล้ว"

## หน้า 12: ยืนยันบนชุด locked: การหยุดช่วย 12 จาก 13 เซลล์

- **คำถาม:** การหยุดช่วยบนข้อมูลที่ไม่เคยเห็นไหม และช่วยทุกโมเดลไหม
- **ทำอะไร:** ลงทะเบียนไว้ก่อน (S1) ว่าสำหรับทุกโมเดลและงานที่โมเดลวนซ้ำอย่างน้อย 5% ของข้อใน calibration การหยุดต้องเพิ่มคะแนน mark มีเซลล์แบบนี้ 13 เซลล์ (S2) การหยุดต้องเปลี่ยน output ที่จบเองไม่เกิน 1%
- **ผล:**
  - **12 จาก 13 เซลล์ผ่าน** เพิ่ม 4.8 ถึง 35.6 จุด (ปรับ Holm แล้ว p ≤ 0.0036)
  - ตัวอย่าง (อ่านทั้งหน้า Δ): โมเดลตั้งต้น +18.4, Qwen3-VL-4B +16.3, SEA-LION +15.2, DeepSeek-OCR-2 +17.1, PaddleOCR-VL +8.4, Wayu +4.8
  - ตัวอย่าง (อ่านข้อความสั้น Δ): โมเดลตั้งต้น +35.6, DeepSeek-OCR-2 +30.0, Wayu +29.1
  - **เซลล์ที่ไม่ผ่าน:** Pathumma อ่านทั้งหน้า +1.3 (ช่วง 0.0 ถึง +3.5, p ปรับแล้ว 0.13) วนซ้ำเพียง 4 จาก 128 หน้า (3.1%) ซึ่งเท่ากับเซลล์ที่เราไม่ได้ทดสอบ โมเดลที่แทบไม่วนซ้ำจึงได้ผลเล็กและยังแสดงไม่ได้ที่ขนาดตัวอย่างนี้
  - **S2 ผ่าน:** เปลี่ยน output ที่จบเอง **1 จาก 2,400** (0.04%, ขอบบน 95% = 0.20%) และเป็น output ของ Typhoon ที่ออกจากการวนซ้ำจริงด้วยตัวเอง
- **แปลว่า:** การหยุดช่วยโมเดลที่วนซ้ำราว 5% ของหน้าขึ้นไป และแทบไม่แตะ output ที่ปกติ
- **ภาพ:** แท่งแนวนอน 8 โมเดล สองแผง (อ่านทั้งหน้า / ข้อความสั้น) แท่งคู่ต่อโมเดล: "greedy" (เทา) กับ "+ หยุด" (เขียวอมฟ้า) ใส่ตัวเลขทั้งสองแท่ง วงหรือป้ายกำกับ Pathumma อ่านทั้งหน้า ว่า "ไม่ผ่านตามเกณฑ์ที่ลงทะเบียน" ใช้ Plotly (ข้อมูลในหน้า 12 ของ paper: `docs/paper/figure_data.json` ส่วน `locked_eight_models_mark_f1`)
- **ต้องบอกด้วย (สำคัญ):** เกณฑ์ที่ลงทะเบียนคือ "ทุกเซลล์ต้องผ่าน" จึง **ไม่ผ่านตามที่ลงทะเบียน** เพราะเซลล์เดียว ให้พูดตรงๆ และอย่าเรียก Pathumma ว่า "ข้อยกเว้นของกลไก" เพราะเป็นเรื่องความถี่ของการวนซ้ำ ไม่ใช่หลักฐานว่าการหยุดไม่ได้ผล บนชุด locked การหยุดตัดแบบ offline
- **พูด:** "12 จาก 13 ไม่ใช่ 13 จาก 13 และผมพูดตัวเลขนี้ตรงๆ"

## หน้า 13: หยุดตอน decode จริงได้เท่ากับการตัดแบบ offline

- **คำถาม:** ตัวเลขหน้า 12 ตัดทีหลังจาก output ครบ ตอนหยุดกลางทางจริงๆ จะเหมือนกันไหม
- **ทำอะไร:** generate ใหม่บนข้อใน calibration โดยต่อตัวหยุดเข้ากับการ generate ครบ 8 โมเดล มี 185 ข้อที่การตัดแบบ offline เปลี่ยน output และสุ่มอีก 72 ข้อที่การตัดไม่แตะ
- **ผล:**
  - output ที่หยุดตอน decode จริง **เท่ากับ** การตัดแบบ offline ทุกตัวอักษรใน **185 จาก 185** ข้อ
  - กฎไม่ทำงานเลยใน **72 จาก 72** ข้อที่ไม่ควรโดนตัด
  - output ที่วนซ้ำใช้ token เพียง **15.3%** ของที่เคยใช้ (86,016 จาก 562,063)
  - ใช้ GPU T4 2.61 ชั่วโมง
- **แปลว่า:** การหยุดทำเป็นกฎตอน decode ได้จริง และให้ผลตรงกับที่วัดแบบ offline
- **ภาพ:** การ์ดตัวเลขใหญ่ 3 ใบ: "185 / 185", "72 / 72", "15.3% ของ token" ตัวเลขสีส้มเหลือง ใต้การ์ดมีป้าย "เฉพาะข้อใน calibration"
- **ต้องบอกด้วย:** ตรวจเฉพาะข้อใน calibration ไม่ใช่ชุด locked และ **ยังไม่ได้วัดเวลาจริงที่ประหยัด** (วัดแค่จำนวน token) ห้ามพูดว่า "ใช้ได้จริงกับข้อมูลที่ไม่เคยเห็นแบบ live"
- **พูด:** "ตรวจว่าวิธีที่ใช้ตัดทีหลังกับวิธีที่หยุดกลางทาง ให้ผลเดียวกัน และได้ตรงทุกข้อ"

## หน้า 14: ใครอยู่อันดับไหน: ตอบอย่างระวัง

- **คำถาม:** Typhoon ดีที่สุดไหม
- **ผล (ชุด locked):**
  - Typhoon สูงกว่า 6 โมเดลอื่น (ไม่รวม Pathumma) ทั้งสองงาน โดยช่วงอยู่เหนือ 0 (เช่น Typhoon − Wayu +19.0 บนหน้าเต็ม, Typhoon − DeepSeek-OCR-2 +57.2)
  - **เทียบ Pathumma ไม่พบความต่าง:** Typhoon − Pathumma (prompt ของ card) อ่านทั้งหน้า +1.5 [−3.1, +6.5] อ่านข้อความสั้น +9.0 [−3.6, +21.3]
  - ตัวเลข locked ของ Typhoon (92.6 / 73.7) ต่ำกว่าตัวเลข calibration (94.9 / 81.7) ซึ่งเป็นปกติบนข้อมูลที่ไม่เคยปรับ จึงอ้างตัวเลข locked
- **แปลว่า:** เรียก Typhoon ว่า "แข็งที่สุดที่วัด และใกล้เคียง Pathumma" ได้เท่านั้น
- **ภาพ:** ตาราง 3 แถว: "Typhoon เหนือ 6 โมเดล" ✔ / "Typhoon vs Pathumma: ไม่พบความต่าง" ≈ / "ตัวเลข locked ต่ำกว่า calibration" ใส่ลูกศรลง
- **ต้องบอกด้วย:** ที่ n = 128 และ 224 ครึ่งความกว้างของช่วงอยู่ราว ±6 และ ±13 จุด จึงไม่ใช่ "เท่ากัน" และต้องมีหมายเหตุติดกับตัวเลข Typhoon และ Pathumma ทุกตัว: Typhoon มาจากกลุ่มที่ทำ benchmark และ Pathumma ไม่ระบุข้อมูลฝึก ส่วน DeepSeek-OCR-2 รัน fp16 อย่างเดียว
- **พูด:** "คำตอบเรื่องอันดับคือ ยังไม่รู้ และผมพูดเท่าที่ข้อมูลรองรับ"

## หน้า 15: ข้อจำกัด

- **คำถาม:** มีอะไรที่ต้องระวังเวลาใช้ผลนี้
- **เนื้อหา (สามกลุ่ม):**
  - **ขอบเขต:** benchmark เดียว สองงาน 8 โมเดลแบบเปิดตามที่เผยแพร่ (visual token ไม่เท่ากัน) โมเดลออกแบบอ่านทีละกรอบสองตัวถูกนำมาอ่านทั้งหน้า DeepSeek-OCR-2 รัน fp16 อย่างเดียว ข้อสรุปเป็นเรื่องกลไก ไม่ใช่อัตรา
  - **การออกแบบ:** กฎการหยุดและตัวชี้วัดเขียนหลังเห็น calibration ชุด locked ยืนยันเฉพาะ 8 โมเดลนี้ **S1 ตามที่ลงทะเบียนไม่ผ่าน** เพราะหนึ่งเซลล์ การหยุดบนชุด locked ทำแบบ offline
  - **การตีความ:** การจัดสาเหตุเป็นแบบอัตโนมัติ "ไม่ปรากฏใน output" ไม่เท่ากับ "อ่านไม่ได้" การทดสอบ forced choice แสดงว่าโมเดลรู้อะไร ไม่ใช่โมเดลทำอะไรตอนเขียน
- **แปลว่า:** ผลนี้บอกว่า mark หายที่ไหน ไม่ได้บอกว่าทำไมโมเดลไม่เขียนข้อความนั้น
- **ภาพ:** สามคอลัมน์ ไอคอนเล็กต่อกลุ่ม ตัวหนังสือสั้นไม่เกิน 3 บรรทัดต่อคอลัมน์ ไม่ใช้สีนอกจากสีน้ำเงินกับเทา
- **ต้องบอกด้วย:** ผลทั้งหมดเป็นผลเบื้องต้น (`PRELIMINARY_PILOT_NOT_GATE_EVIDENCE`) ไม่ได้เปิดหรือผ่าน gate ใด
- **พูด:** "หน้านี้ไม่ใช่หน้าขอโทษ แต่คือขอบเขตที่ผมรับรองได้"

## หน้า 16: สรุป และขั้นต่อไป

- **คำถาม:** ตอบคำถามเปิดเรื่องว่าอย่างไร และทำอะไรต่อ
- **สรุป 3 ข้อ:**
  1. **mark ส่วนใหญ่ไม่ใช่จุดอ่อน:** ใน 8 โมเดลบนชุด locked ข้อความที่ไม่ปรากฏใน output เสีย mark มากกว่าการอ่านผิด 4.7–15.8 เท่า
  2. **เมื่อให้บริบทถูก วรรณยุกต์ถูกราว 99%** กับ Thai fine-tune สองตัว (Qwen3-VL-4B รู้เท่ากันแต่เขียนผิดบ้าง)
  3. **หยุดเมื่อวนซ้ำเป็นวิธีที่ปลอดภัย:** เพิ่มคะแนนใน 12 จาก 13 เซลล์ที่ลงทะเบียน และเปลี่ยน output ที่จบเอง 1 จาก 2,400
- **ขั้นต่อไป (ยังไม่ได้ทำ):**
  - แยก "โมเดลข้ามบรรทัดที่มองเห็นอยู่" ออกจาก "อ่านไม่ออกจริง" ด้วยการวัดระดับบรรทัด (ป้อนข้อความที่ถูกถึงก่อนบรรทัดที่หาย แล้วดูว่าโมเดลเขียนบรรทัดนั้นได้ไหม)
  - ทดสอบบน benchmark ที่สอง
  - วัดเวลาจริงของการหยุดตอน decode
- **ภาพ:** สามการ์ดตัวเลขใหญ่ (4.7–15.8 เท่า / ~99% / 12 จาก 13) ใต้การ์ดเป็นบรรทัด "ขั้นต่อไป" สามข้อสั้นๆ
- **ต้องบอกด้วย:** ขั้นต่อไปเป็นแผน ไม่ใช่ผลที่ทำแล้ว
- **พูด:** "คำตอบของคำถามที่ถามตอนแรก: ส่วนใหญ่ไม่ใช่ จุดอ่อนอยู่ที่ข้อความไม่ถูกเขียนออกมา"

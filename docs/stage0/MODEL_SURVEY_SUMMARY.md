# สรุปผล Track E (MODEL_SURVEY M1–M4): โมเดลอื่นเทียบ Typhoon และการแก้ loop ของ Wayu

**ระดับข้อสรุป:** `PRELIMINARY_PILOT_NOT_GATE_EVIDENCE`

- ใช้เฉพาะ calibration split (178 ข้อ) ไม่แตะ locked split
- ไม่มีผลใดเปิดหรือผ่าน gate
- ผู้อนุมัติ: M1–M4 ได้รับอนุมัติจาก PELY334 และ Up2mEz ครบแล้ว (Up2mEz review เมื่อ 2026-10-11 หลังรันเสร็จ)
- เอกสารฉบับเต็มของแต่ละขั้นอยู่ใน `docs/stage0/MODEL_SURVEY_M*_REGISTRATION.md` และ `MODEL_SURVEY_M*_RESULTS.md`

## สรุปสั้นที่สุด

**ไม่มีโมเดลใหม่ตัวไหนอ่านวรรณยุกต์และสระไทยได้ดีเท่า Typhoon OCR 1.5** ใน 3 โมเดลที่ลอง wayu-paxa-ocr-zero ดีที่สุด

Wayu เสียคะแนนไปส่วนหนึ่งกับ repetition loop (วนซ้ำจนเต็มจำนวน token) ผลของวิธีแก้ loop แต่ละแบบ:

| วิธี | ผล |
|---|---|
| decoding ตามที่ model card แนะนำ | ไม่ช่วย |
| ตัวหยุด loop ของ T5b | ช่วยมาก (+11 / +24 mark F1) |
| การบังคับให้อ่านต่อหลัง loop (escape) | อ่านกลับคืนได้บางหน้า แต่แต่งข้อความเพิ่มในอีกหลายหน้า |
| ตัวกรองด้วยความมั่นใจของโมเดล | แยกข้อความจริงกับข้อความแต่งได้ (AUROC 0.92) แต่ส่วนหนึ่งมาจาก token ที่ escape บังคับ และข้อความที่กู้คืนได้มีน้อย |

**ช่องว่างราว 18 จุดกับ Typhoon บน Full-page อยู่บนหน้าที่ Wayu วน loop และไม่มีวิธี decoding ที่ลองแล้วกู้คืนได้** ยังแยกไม่ได้ว่า loop เป็นสาเหตุของข้อความที่ไม่ได้อ่าน หรือเป็นอาการของการอ่านไม่ออก

## วิธีประเมินที่ใช้ร่วมกันทุกขั้น (protocol ของ T1)

**ข้อมูลและการตั้งค่า**

- **ข้อมูล:** ThaiOCRBench (`ca610d1ab330`) calibration split 178 ข้อ (Full-page OCR 69 ข้อ, Text recognition 109 ข้อ) seed 20260927
- **ภาพ:** image policy ตาม model card ของ Typhoon (ด้านยาว 1800 px)
- **decoding:** greedy, `max_new_tokens` 3072, fp16 (fallback fp32), `sdpa`
- **เครื่อง:** Kaggle 2×T4, quota ของ PELY334

**ตัววัด**

- **mark F1 แบบ order-free (v2):** recall และ precision ของวรรณยุกต์/สระบน-ล่าง ไม่ลงโทษลำดับบรรทัด แต่ลงโทษข้อความส่วนเกิน
- **T1 scoring v2:** anchored CER, tone error เมื่ออ่าน consonant ถูก, truncation rate
- **matched lines:** จำนวนบรรทัดของ reference ที่หาเจอใน output ที่ CER < 0.4 ใช้ตั้งแต่ M3 เพื่อกัน credit ที่ได้มาโดยบังเอิญ

**สถิติ:** paired item bootstrap 2,000 รอบ รายงาน 95% interval ทุกตัว ตีความ "เพิ่ม/ลด" จาก interval เท่านั้น

**การตรวจก่อนอ่านผล**

- ผลซ้ำได้: คะแนน Typhoon และ base ตรงกับ T1 ทุกครั้ง
- control รันซ้ำแล้วต้องได้ output ตรงกับรอบก่อนทุก token
- ตรวจ markup (HTML/markdown) ใน output ทุกครั้ง ทุกรอบไม่พบ HTML

**กติกาการทดลอง**

- ลงทะเบียน (registration) ก่อนรัน และกำหนดล่วงหน้าว่าผลแต่ละแบบจะแปลว่าอะไร
- smoke ก่อนรันเต็ม
- ไม่เขียนทับผลเดิม
- ทุก run บันทึก commit, config และ environment

## วิธีที่ลองทั้งหมดและผล

### 1. ลองโมเดลใหม่ (M1)

Mark F1 ของแต่ละโมเดล

| โมเดล | prompt | Full-page | Text recognition |
|---|---|---:|---:|
| **Typhoon OCR 1.5** (T1) | BQ | **94.9** | **81.7** |
| base Qwen3-VL-2B (T1) | BQ | 41.0 | 24.3 |
| Qwen3-VL-4B | BQ | 45.9 | 23.5 |
| PaddleOCR-VL-1.6 | `OCR:` | 53.3 | 47.9 |
| wayu-paxa-ocr-zero | `OCR:` | 65.2 | 46.0 |

ทำไมแต่ละโมเดลถึงได้ผลแบบนี้

| โมเดล | สิ่งที่ทดสอบ | ผล | สรุป |
|---|---|---|---|
| **Qwen3-VL-4B** | ขยายขนาดจาก base 2B เป็น 4B | F1 +5.0 [−4.0, +14.1] จาก base (Full-page) | ✗ ขนาดอย่างเดียวไม่ปิดช่องว่าง ช่วยลด loop (43.5% → 27.5%) แต่ไม่ช่วยเรื่องวรรณยุกต์ |
| **PaddleOCR-VL-1.6** | OCR model เฉพาะทาง ขนาด 0.9B | ต่ำกว่า Typhoon ราว 34–42 จุด (Full-page −41.6, Text recognition −33.9) | ✗ |
| **wayu-paxa-ocr-zero** | Paddle-VL ที่ fine-tune ด้วยข้อมูลไทยสังเคราะห์ | ดีที่สุดในโมเดลใหม่ แต่วน loop 26% (Full-page) / 20% (Text recognition) | △ อ่านได้ดีในข้อที่ไม่วน แต่ยังต่ำกว่า Typhoon |

หมายเหตุ M1:

- ทุกโมเดลใหม่ต่ำกว่า Typhoon โดย interval ต่ำกว่า 0 อย่างน้อย 14 จุด
- ในข้อที่ไม่มีใคร loop Typhoon ยังนำ Wayu 10 จุด (Full-page)
- โมเดลตระกูล Qwen ใช้ visual token เยอะกว่า: ราว 2,240–2,352 เทียบกับ Paddle และ Wayu ราว 1,250 การเทียบนี้จึงเป็นการเทียบโมเดลตามที่ปล่อยมา ไม่ใช่ที่ token budget เท่ากัน

### 2. แก้ loop ของ Wayu ด้วย decoding (M2)

| วิธี | ทำอะไร | ผล (mark F1 เทียบ greedy) | สรุป |
|---|---|---|---|
| **R105**: `repetition_penalty` 1.05 | penalty ตามที่ model card แนะนำ | Full-page +2.8 [−3.6, +9.6], Text recognition −11.3 [−22.5, +4.5] | ✗ loop ลดลงเล็กน้อย แต่ loop ที่เหลือเปลี่ยนจากวนตัวเลขเป็นวนคำไทย precision จึงแย่ลง |
| **CARD**: sampling ตาม card (T 0.1, top_p 0.7, penalty 1.05) | sampling 1 seed ต่อข้อ | Full-page −0.0, Text recognition −10.7 | ✗ ไม่ดีกว่า R105 |
| **T5b stop (+B)** | หยุดเมื่อเจอสำเนาซ้ำครบ 8 ครั้ง แล้วเก็บไว้สำเนาเดียว (offline) | **Full-page +10.8 [+5.3, +16.1], Text recognition +24.4 [+10.7, +35.7]** และประหยัด token ~34% / ~29% | ✓ **ได้ผลที่สุด** |

หมายเหตุ M2:

- **control ผ่าน:** greedy ที่รันซ้ำให้ output ตรงกับ M1 ทุก token (20/20 ข้อ)
- **พบจุดอ่อนของ metric:** order-free metric ให้ credit กับข้อความที่วนซ้ำโดยบังเอิญ (recall เกินจริง 3.3 จุดใน Wayu) ข้อนี้กระทบทุกโมเดลที่ loop และได้แจ้ง Up2mEz ผู้ดูแล metric แล้ว
- **ข้อความที่ loop ทำให้ไม่ได้อ่าน:** 72% ของ recall gap ของ Wayu บน Full-page อยู่ใน 18 หน้าที่วน ตัวหยุดคืนส่วนนี้ให้ไม่ได้
- **หลังใช้ตัวหยุดยังต่ำกว่า Typhoon:** −17.9 (Full-page) และ −11.3 (Text recognition)

### 3. บังคับให้อ่านต่อหลัง loop: loop escape (M3)

| วิธี | ทำอะไร | ผล (Full-page, เทียบหยุดเฉย ๆ) | สรุป |
|---|---|---|---|
| **escape** | เมื่อเจอ loop ย้อนกลับไปท้ายสำเนาแรก ห้ามเขียนหน่วยที่วนซ้ำอีก แล้วให้ decode ต่อ (สูงสุด 8 ครั้ง) | recall +2.3 [+0.7, +4.2], matched lines **+23** [+5, +47], precision −2.6, **F1 +0.5** [−0.6, +2.0] | △ อ่านกลับมาได้จริงบางหน้า แต่แต่งข้อความในอีกหลายหน้า |
| **Addendum 1** (แก้หลัง smoke) | ตัวตรวจ loop หลัง escape มองเลขทุกชุดเป็นตัวเดียวกัน | ปิดช่องที่โมเดลเลี่ยงด้วยการใส่เลขลำดับ ("5) …", "6) …") | ✓ จำเป็น |

หมายเหตุ M3:

- **ตัวอย่างที่สำเร็จ:** F096D392 ซึ่ง greedy วนตั้งแต่ตัวอักษรแรก หลัง escape อ่านได้ครบ 9/9 บรรทัด
- **ตัวอย่างที่ล้มเหลว:** หน้าอื่น ๆ ได้ภาษาไทยลื่น ๆ ที่ไม่มีในภาพ
- **Text recognition:** F1 −2.0 [−4.3, −0.4] เพราะข้อความที่เพิ่มมาเป็นส่วนเกิน
- **control ผ่าน:** 158/158 ข้อที่ไม่ escape ตรงกับ greedy ทุก token
- **ตัวเทียบ E0:** "หยุดเฉย ๆ" ในรันเดียวกัน ให้ผลเท่ากับตัวหยุดของ M2 ทุกช่อง

### 4. กรองด้วยความมั่นใจของโมเดลเอง (M4)

| วิธี | ทำอะไร | ผล | สรุป |
|---|---|---|---|
| **confidence (log-prob) แบบ teacher-forced** | คิดคะแนน output เดิมของ M3 โดยไม่ generate ใหม่ หน่วยคือหน้าต่าง 20 ตัวอักษร | **AUROC 0.92** [0.81, 0.98] แยกข้อความที่อ่านจริงกับข้อความที่แต่ง (s_min 0.92, entropy 0.84) | △ ส่วนหนึ่งเป็นผลของ token ที่ escape บังคับ (ดูการตรวจ confound ด้านล่าง) |
| **ตัวกรอง** | ทิ้งหน้าต่างหลัง escape ที่ความมั่นใจต่ำกว่า percentile 10 ของข้อความปกติ (เกณฑ์กำหนดโดยไม่ดู label) | เก็บข้อความจริง 70% ทิ้งข้อความแต่ง 93% precision ที่เสีย −2.6 → −0.4 แต่ **F1 +0.5** [−0.3, +1.6] | △ ลบความเสียหายได้ แต่ข้อความที่กู้คืนได้มีน้อยเกินกว่าจะขยับ F1 |

หมายเหตุ M4:

- **control ผ่าน:** argmax แบบ teacher-forced ตรงกับ token 99.7% ในข้อความปกติ
- **เทียบ Typhoon:** ยังต่ำกว่า −18.4 (Full-page)
- **การตรวจ confound (Up2mEz ขอหลัง review, exploratory):** token ที่ escape บังคับมี log-prob ต่ำโดยปริยาย และพบบ่อยในข้อความแต่ง (50/84 หน้าต่าง เทียบกับ 4/46 ในข้อความจริง)
  - สัดส่วน token ที่ถูกบังคับอย่างเดียวได้ AUROC 0.76 (ภายในหน้าเดียวกัน 0.63)
  - s_mean นับเฉพาะ token ที่ไม่ถูกบังคับ: 0.80 [0.57, 0.92] (ภายในหน้า 0.83)
  - s_mean เฉพาะหน้าต่างที่ไม่มี token ถูกบังคับเลย: 0.92 [0.78, 0.99] แต่มาจาก 6 หน้า (ภายในหน้า 0.84 จาก 3 หน้า)
  - baseline ที่ไม่ใช้โมเดล (ระยะจากจุด escape, ความยาวหน้าต่าง) แยกได้ระดับหน้า แต่ภายในหน้าใกล้ระดับสุ่ม
  - label เกือบแยกตามหน้า: 28 จาก 46 หน้าต่างที่อ่านจริงมาจาก 2 หน้า จึงมีหน้าที่ผสมทั้งสอง label จริงราว 4 หน้า ถ้าตัดออกทีละหน้า AUROC แบบไม่นับ token ที่ถูกบังคับอยู่ระหว่าง 0.70–0.85 (0.70 เมื่อตัด F096D392)
  - **สรุป:** สัญญาณมีอยู่จริงเกินกว่าผลของการบังคับ แต่อ่อนลงและอิงข้อมูลราว 4 หน้า ข้อความเดิม "Wayu รู้ตัวว่ากำลังแต่ง" และ "ขยายผล E1 ไปโมเดลที่สอง" จึงถอนออก
  - **สถานะสำหรับ paper: ไม่อ้างอิง M4** (not cited; confound with forced tokens unresolved)
  - ตารางรายหน้าต่าง: `docs/stage0/data/M4_WINDOWS_a9aad7aa31d8.json` (`scripts/model_survey_m4_confound.py`)

## ข้อจำกัดและสิ่งที่ยังไม่แน่ใจ

- **ขอบเขตข้อมูล:** ใช้ calibration split ชุดเดียว รันละครั้ง ข้อสรุปจำกัดอยู่ที่ 5 checkpoint นี้
- **ข้อมูลที่ใช้ออกแบบกับข้อมูลที่ใช้ทดสอบเป็นชุดเดียวกัน:** M3 และ M4 ออกแบบบนข้อมูลชุดเดียวกับที่ใช้ทดสอบ ถ้าจะยืนยันต้องใช้ข้อมูลที่ไม่เคยใช้ (locked split) ซึ่งต้องตัดสินใจร่วมกันสองคน
- **การแก้ design หลังเห็นข้อมูล:** M3 Addendum 1 แก้หลังเห็น smoke ไป 1 ข้อ บันทึกไว้แล้วในเอกสาร
- **ข้อจำกัดของ label ใน M4:**
  - label ทั้งหมดมาจาก 10 หน้า และ 5 หน้ามีหน้าต่างเกือบทั้งหมด interval จึงกว้าง
  - หน้าต่าง 20 ตัวอักษรอาจบังเอิญตรงกับ reference ได้ ซึ่งถ้ามีจะทำให้ AUROC ต่ำลง ไม่ใช่สูงขึ้น
- **loop ที่ไม่มีตัวอักษร** เช่น "๒ ๒ ๒" หรือ "3 3 3" ไม่ถูกตัดโดยตัวหยุดหรือ escape ตามที่ออกแบบไว้เพื่อไม่ให้ไปตัดเส้นประในเอกสาร loop แบบนี้ไม่กระทบ mark F1 แต่ทำให้ output ยาวขึ้น

## ข้อเสนอขั้นต่อไป (ยังไม่ได้อนุมัติ)

1. **ไม่แนะนำให้ทำ decoding ของ Wayu ต่อ** ทั้งหยุด, escape และกรองไม่เปลี่ยนช่องว่างกับ Typhoon ช่องว่างอยู่บนหน้าที่วน loop แต่ยังแยกไม่ได้ว่า loop เป็นเหตุหรืออาการ
2. **ถ้าใช้ Wayu ต่อ** ให้ใช้ greedy + ตัวหยุด T5b
3. **ข้อค้นพบที่ใช้ต่อได้:** ความมั่นใจของโมเดลชี้ข้อความที่ไม่น่าเชื่อถือได้
   - Typhoon: ชี้ตำแหน่งที่วรรณยุกต์ผิด (E1, AUROC 0.94–0.95) บน output greedy ที่ไม่มีการบังคับ token
   - Wayu: ผลของ M4 สอดคล้องกับ E1 แต่ยังไม่นับว่าทำซ้ำ E1 ได้ เพราะส่วนหนึ่งของสัญญาณมาจาก token ที่ escape บังคับ และส่วนที่เหลืออิงข้อมูล 3–6 หน้า
   - ที่ใช้ที่เหมาะคือ flag ข้อความเพื่อส่งไปอ่านซ้ำ
4. **การอ่านทีละ region** เป็นทางเลือกฝั่ง input และอยู่ใน track ของ Up2mEz
